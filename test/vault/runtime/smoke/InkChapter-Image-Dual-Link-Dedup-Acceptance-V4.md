# 墨章图片双链与智能去重验收（V4）

> 用途：在真实 Typora 中人工验收「本地已有就复用、GitHub 已有就复用远端、缺失时才传输」。
> 本文件所有图片均使用 GitHub 图床链接，便于验证远程复用与下载去重。
> 结论填写在文末记录表；不要在此文件中粘贴 Token、本机绝对路径或私有配置。

## 前置条件

1. 已在「设置 → 墨章 · 图片」启用图片管理。
2. 需要验证上传时：上传服务为 GitHub，且已保存 Token、远程配置可用。
3. 需要验证「上传服务为无」时：把上传服务切回「无」，不要删除远程配置本身。
4. 验收过程中不要手工改写下方图片引用，由插件动作或 Typora 原生行为完成。

## 用例 1：GitHub 已有同内容图片，再次上传应零上传

1. 把下面这张图（boundary-a）保存到本地任意测试目录，文件名可改为 `reuse-a.png`。
2. 执行「墨章：上传本地图片…」两次。
3. 期望：第一次提示「已上传新图片（1 次上传）」；第二次提示
   「GitHub 已有相同图片，已直接复用云端链接，无需重复上传（0 次上传）」。
4. 期望：图床仓库中不新增第二份文件。

![边界图 A](https://raw.githubusercontent.com/MoRanzhi1203/Picture_Bed/main/images/20261104-102331-7d5d02a14e.png)

## 用例 2：目标仓库已有同内容、但文件名不同，应识别并复用

1. 用另一个工具把 boundary-b 上传到同一远程目录，文件名改为 `renamed-b.png`。
2. 在 Typora 中执行「墨章：上传本地图片…」上传本地同名 boundary-b 原图。
3. 期望：复用远程既有 URL，0 次新上传；诊断视图中的任务结果应显示 `REUSED_REMOTE`。

![边界图 B](https://raw.githubusercontent.com/MoRanzhi1203/Picture_Bed/main/images/20261104-112626-9e8256de51.png)

## 用例 3：项目本地已匹配，执行下载应零下载、零复制

1. 先把 boundary-a 下载到当前文档的图片目录（仅建立本地位置）。
2. 再次对同一张远程图执行「下载并转为本地引用」。
3. 期望：提示「本地已有相同图片，已直接复用，无需重复下载」，网络传输 0 次，
   正文只更新当前图片的 destination。

## 用例 4：仅图库有匹配，请求项目副本时应本地复制

1. 把 boundary-b 先「下载到全局图库」。
2. 再从同为 boundary-b 的远程引用执行「下载并转为本地引用」（目标为项目目录）。
3. 期望：提示「已复用本地已有图片并复制到目标目录，无需联网下载」；
   断网执行也应成功；网络传输 0 次、本地复制 1 次。

## 用例 5：同名不同内容，禁止覆盖

1. 在项目图片目录放置一个与远程图**同名但内容不同**的 `phase6-test.png`。
2. 对该远程图执行「下载并转为本地引用」。
3. 期望：原文件内容保持不变；新文件追加内容哈希后缀；Markdown 引用指向新文件。

![阶段 6 测试图](https://raw.githubusercontent.com/MoRanzhi1203/Picture_Bed/main/images/20261104-112015-497790947d.png)

## 用例 6：上传服务为「无」

1. 将上传服务切为「无」。
2. 执行「墨章：上传本地图片…」。
3. 期望：明确提示上传服务为「无」、未发起上传；图床不新增文件。
4. 期望：本地插入、已有远程图片的下载与显示仍然正常。

## 用例 7：引用语义与正文纯净

1. 对同一张远程图片，右键选择「下载并转为本地引用（墨章）」。
2. 期望：alt、图号、图名、图注与周围正文不变；只改该图片的 destination。
3. 对已经是本地引用的图片重复执行，期望提示引用已正确、正文不发生重载。
4. 上传/下载后检查 Markdown 源码：不得出现「编辑图名」「清除图名」「复制本地路径」
   「复制 Markdown 引用」等工具栏文字；同一张图只应有一个工具栏。

## 用例 8：批量下载统计

1. 打开包含多张远程图片的文档，执行「墨章：下载本文档全部远程图片」。
2. 期望提示同时给出：复用张数、实际下载张数、本地复制张数、失败张数、网络传输次数。
3. 期望：Markdown 正文不被修改。
