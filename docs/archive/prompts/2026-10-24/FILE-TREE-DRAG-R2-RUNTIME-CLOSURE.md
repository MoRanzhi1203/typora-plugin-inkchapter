## 2. 最先确认的能力和风险

### 2.1 外部拖入

- 检查捕获监听仅在 `#file-library-tree` 的外部 `Files` 拖拽生效；验证 `dragenter` / `dragover` / `drop` 的事件顺序、`defaultPrevented`、`stopPropagation`、`dropEffect`、外部/内部源判别、目标路径、复制服务调用次数。
- 真实检查原生 `copyOrMoveFiles → execRenameFileByNode → rename` 是否被阻断；**保留源文件**为硬门禁。不要因为测试桩的 `nativeMoveHandlerRan=false` 就宣布原生操作被阻断。
- 路径优先走当前 Typora 实际支持的文件路径提取；检查 `File.path` 与可用的替代机制。缺少可信路径时拒绝并提示，不能猜测。
- 验证目标：树根目录、已展开子目录、未展开子目录、文件节点所在目录；外部多文件、不同扩展名、空文件、中文/空格/Unicode 文件名。
- 安全策略：检查源文件是否普通文件；禁止不可信符号链接和目录越界；复核 realpath；同名默认保留两个、禁止默认覆盖；拒绝目录及非 Markdown 文件；目标不可写要反馈；确保异常后不执行原生移动。
- 增量刷新 `fileTree.onChangeForWin` 与原生 watcher 同时触发不得产生重复树节点、滚动跳变或展开状态丢失。

### 2.2 向外拖出

- 优先保留 Typora 现有原生 `dragstart` / `ondragstart` IPC；墨章不得重复发 IPC、劫持或重新实现系统拖拽。
- 真实验证从文件树拖到 Windows 桌面和资源管理器目录是否产生文件，核实目标字节和源路径仍存在；明确 Windows OS 拖放效果可能受修饰键、同盘/跨盘和目标应用影响，不能无依据声称始终 Copy。
- 识别当前打开文件的未保存状态，提示拖出的是磁盘版本；不得自动保存用户正文。
- 若系统端不能提供可靠复制语义，记录限制，并给出真实可用的替代操作：在资源管理器定位源文件后使用 Ctrl+C / Ctrl+V；“复制路径”只是辅助，不得宣传为复制文件。

## 3. D01–D12 实机验收矩阵（必须逐项形成收据）

测试必须使用新建的临时源目录/目标目录与专用 `.md` 样本，不得使用用户重要文档；每项重置初始状态。

| ID | 真实动作 | 必须满足 |
|---|---|---|
| D01 | Explorer 单个 `.md` 拖入文件树根部 | 正确复制，源仍在，目标 SHA 一致 |
| D02 | 拖入已展开子文件夹 | 路径正确，文件树及时显示，无重复节点 |
| D03 | 拖入未展开子文件夹 | 首次展开时可见，原展开/滚动状态未损坏 |
| D04 | 同时拖入多个 `.md` / `.markdown` | 每个文件分别复制，无漏项、无源删除 |
| D05 | 同名文件重复拖入 | 自动生成 `名称 (2).md` 等，原目标保持不变 |
| D06 | 拖入 `.txt`、目录、符号链接或无效来源 | 明确拒绝且不产生移动/异常文件 |
| D07 | 文件树内部拖放 | 仍由 Typora 原生处理，不误触发外部复制逻辑；仅在安全测试样本中操作 |
| D08 | Explorer `.md` 拖入编辑器正文 | 保持 Typora 原生编辑器拖放，不被文件树增强截获 |
| D09 | 文件树 `.md` 拖出至 Windows 桌面 | 确认实际生成副本及源存在；记录 Windows 最终操作类型 |
| D10 | 文件树 `.md` 拖出至资源管理器另一目录 | SHA 对比，源存在，记录同盘/跨盘条件 |
| D11 | 打开且未保存的 Markdown 向外拖出 | 明确提醒磁盘版本，不自动保存，不修改正文 |
| D12 | 快速重复拖入、取消、Esc、拖拽离开窗口 | 不重复复制、不漏清高亮、不回退到原生移动 |

必须补测：Windows 中文文件名、CRLF/LF 字节原样复制、0 字节 Markdown、只读目录、同名大小写差异、文件夹刷新时滚动/折叠/侧栏宽度变化，以及重启/切换 vault 后监听器不重复安装。

**每条验收收据应包含：** 当前 PID/文档或 vault/加载 SHA、原文件路径与目标路径（报告中隐去无关隐私）、文件前后存在性、源/目标字节长度与 SHA256、源文件是否变化、DragEvent 关键属性、复制服务结果、刷新状态、明确 PASS/FAIL/NOT_RUN；真实鼠标拖拽应记录可信输入来源，不得用程序合成 `DragEvent` 冒充真实 OS 操作。

## 4. FAIL 后的定点修复规则

1. **未拦截原生移动**：先确认事件流与监听安装时机，准确修复捕获位置和识别条件；严禁全局禁用拖放和编辑器原生输入。
2. **源路径取不到**：验证当前 Electron/Typora 能力，使用实际支持的接口；不可用则明确 BLOCKED，不虚构文件路径。
3. **已复制但文件树不刷新**：沿 `copy → onChangeForWin → watcher → DOM 节点` 查找失效点，做最小增量通知，保持侧栏滚动和展开状态。
4. **重复文件或过时状态**：检查并发复制、监听器重复安装、异步回调和冲突重命名原子性；基于当前 vault 身份拒绝跨库过期任务。
5. **向外拖出不工作**：验证 Typora 原生拖拽链是否真实启动；不得调用未经证实的 IPC 或侵入主进程；无法修复时明确限制与 Explorer 复制替代流程。
6. **发生文件内容或源文件变化**：立即停止该测试，保留证据及可恢复副本，对行为根因定点修复；未经许可不得覆盖/回滚用户原文。
