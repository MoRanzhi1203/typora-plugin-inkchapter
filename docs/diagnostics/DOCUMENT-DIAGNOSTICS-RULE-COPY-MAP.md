## 文案规范化记录（现状 → 建议）

### 严重程度前缀

- 现状：消息内嵌 `警告：…` / `⚠ 严格模式结构错误：…`，与其它规则不一致
- 建议：标题/说明不含严重程度前缀；严重程度只由颜色/图标表达
- 涉及规则：`DOCUMENT_TERMINAL_NEWLINE_MISSING`、`DOCUMENT_TRAILING_BLANK_LINES_EXCESSIVE`、`STRICT_FIRST_H1_POSITION`

### 术语统一

- 现状：同一概念出现多种叫法（图名 / 图片名称、表名 / 表格名称、代码名 / 代码块名称）
- 建议：统一为「图片/图名、表格/表名、代码块/代码块名称」
- 涉及规则：`FIGURE_MISSING_NAME`、`FIGURE_DUPLICATE_NAME`、`TABLE_MISSING_NAME`、`CODE_MISSING_NAME`、`CODE_DUPLICATE_NAME`

### 编号提示统一

- 现状：「编号重复：N」「编号顺序异常：N」说法零散
- 建议：统一为「<对象>编号重复/顺序异常」+ 一致说明与修复建议
- 涉及规则：`FIGURE_NUMBER_DUPLICATE`、`TABLE_NUMBER_DUPLICATE`、`CODE_NUMBER_DUPLICATE`、`FIGURE_NUMBER_ORDER_INVALID`、`TABLE_NUMBER_ORDER_INVALID`、`CODE_NUMBER_ORDER_INVALID`、`FORMULA_NUMBER_ORDER_INVALID`

### 重复警告统一

- 现状：「重复的图名「X」」「重复的表名「X」」「重复的标题文字「X」」句式不一
- 建议：统一为「<对象>名称重复」/「标题文字重复」，并统一建议「…以互相区分」
- 涉及规则：`FIGURE_DUPLICATE_NAME`、`TABLE_DUPLICATE_NAME`、`CODE_DUPLICATE_NAME`、`HEADING_DUPLICATE_TEXT`

### 标题句式统一

- 现状：「存在空标题」「标题存在重复的规范身份」等主语/句式不一致
- 建议：统一为陈述式名词短语（如「标题为空」「标题规范身份重复」）
- 涉及规则：`HEADING_EMPTY_TEXT`、`HEADING_DUPLICATE_IDENTITY`

### 文档完整性统一

- 现状：「文档仅包含标题」与「文档只有标题结构」用词不一
- 建议：统一为「文档仅包含标题 / 文档仅包含标题结构」
- 涉及规则：`DOCUMENT_HEADING_ONLY_NO_BODY`、`DOCUMENT_HEADINGS_ONLY_NO_BODY`

### 中英文/格式统一

- 现状：`Front Matter`、`$$`、`H1` 等中英混排前后空格与标点不统一
- 建议：统一中英文间空格、统一使用中文顿号与「」引号、统一句末标点
- 涉及规则：`FRONTMATTER_UNCLOSED`、`FORMULA_BLOCK_UNCLOSED`、`HEADING_LEVEL_GAP`、`LATENT_ATX_HEADING_MARKER`

## 排序与视图

- 默认排序：Markdown 源码位置（band → 行 → 列），文末问题（document-end）始终最后。
- 同位置并列：严重程度（错误 → 警告 → 提示）→ 稳定规则优先级（`DOCUMENT_DIAGNOSTIC_RULE_PRIORITY`）。
- 可切换排序：按位置 / 按严重程度 / 按问题类型；可按问题类型筛选；可选按问题类型分组。
- 筛选只删除条目、绝不重排幸存项；分组只是叠加展示、不改变组内顺序。
