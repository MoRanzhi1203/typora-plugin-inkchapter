## 0. 总目标与不可更改的产品约束

本次整合此前两轮需求，目标为：右上角以一个三色状态小方块取代冗长的“文档检测数量 + 编辑/锁定”常驻按钮；锁定时保留诊断颜色并在小方块外围加一圈明显、独立的边框；点击小方块打开统一的“墨章文档管理中心”，提供文档检测、文档锁定、当前文档图片配置及一键上传全部图片、一键下载全部图片、检查/补齐双链、修复引用等能力。同时引入首次启用引导、图链/图片配置变更后的差异提醒、目标目录或资源缺失时的安全确认流程。

硬约束：

1. **Typora 原生六种插入方式名称、顺序、语义必须保留**：无特殊操作；复制到当前文件夹 `./`；复制到 `./assets`；复制到 `./${filename}.assets`；上传图片；复制到指定路径。不得以“仅本地/仅远程/双存储”取代它们。
2. 全局默认模板、用户明确指定的文件夹范围、单个已保存 Markdown 文档三级配置；当前文档覆盖 > 最具体有效文件夹规则 > 全局默认模板，但**继承参数不等于自动授权执行文件操作**。
3. 全局图库位置和文档管理作用范围完全独立；设置了 `E:` 盘或任意图库不意味着扫描、管理、迁移其中所有 Markdown。
4. **零无授权目录创建**：打开文档、切标签、启动插件、查看状态、索引检查、切换模式、保存配置、建立逻辑双链映射，不得自行创建 `assets/`、`${filename}.assets/` 或项目旁的其他图片目录。Typora 原生插入实际需要创建目录时遵循原生行为；用户明确确认的落盘、归档、下载、迁移才可按需创建真实目标目录。
5. 已有资源优先复用：`REUSED_REMOTE` / `REUSED_LOCAL` / `COPIED_EXISTING_LOCAL` / `UPLOADED_NEW` / `DOWNLOADED_NEW` / `ALREADY_LINKED` 必须保留；同名不等于同内容，按经过验证的内容版本去重。不能仅根据 URL 或索引记录声称资源存在。
6. 配置变更与现有图片迁移、上传、下载、引用改写严格分离；**默认关闭自动传输和自动改写 Markdown**。
7. 不修改 Typora 安装目录、社区框架，不升级 Typora，不插入任何插件 UI 节点至可序列化的 Markdown 编辑内容，不改变图号、图名、正文、原生菜单与撤销/重做。
8. GitHub Token/DPAPI 凭据及个人绝对路径不得被提交、日志输出或包含在公开测试材料中。
9. 严禁通过删除关键断言或降低覆盖率制造全绿；本地离线夹具与 GitHub 远程夹具分别保持真实覆盖，重复 URL 的不同文档引用必须独立定位。

建议是轻量 popover，宽度约 340–380px、最大高度受窗口约束，内部可滚动。不要同时弹出多个菜单或遮挡原生菜单；禁止插入 `#write` 或任何可编辑/Markdown 序列化区域。统一包含：

显示错误/警告真实数量，支持“查看详情”“重新检测”“定位问题”；复用现有诊断服务，不重复发起昂贵全量扫描。弹窗关闭后清理订阅。

### D3.4 图片管理摘要

- 一键下载本文全部远程图片；
- 检查并补齐本文图片双链；

- 查看当前文档图片资产/图库中心；

## D4. 全局、文件夹、文档三级策略与原生六项保持一致

1. 全局默认**只是模板**；真正自动执行须有独立明确的授权范围。文件夹规则用户指定且可递归；独立 `.md` 可按文件级覆盖。文件重命名、移动、另存为、同名文件、文档切换不可串配置。
2. 单文档管理中心快捷选择：继承 / 当前文档独立配置 / 仅 Typora 原生（禁用墨章主动图片处理）。字段允许单独覆盖，不复制整个配置。
3. 六种原生插入方式始终完整展示，不能在文档级自创新模式。Typora 原生“插入图片时”是应用级设置的可能性须实测审计：未验证实际逐文档执行机制时只允许清楚显示“已保存策略，插入时自动应用尚不可用”，不能频繁修改 Typora 全局插入设置伪装独立生效。
4. **插入方式决定未来实际插图操作**；“当前文档首选云端 URL/本地引用”属于后续**显式引用转换**偏好；“本地+远程双链”是资产位置登记能力，并不要求立刻复制两份物理文件。
5. 自动同步默认关闭；若选择上传方式但上传服务为 `none`，展示配置冲突，不静默上传、丢弃图片或改变原生行为。

## D5. 当前文档批量上传/下载/双链补齐

### D5.1 操作语义

- **上传本文全部图片**：解析当前文档的可上传本地图片或可通过已验证本地位置关联的资产；根据有效 GitHub Profile 查找远程匹配，已有直接 `REUSED_REMOTE`，否则才 `UPLOADED_NEW`。默认保留 Markdown 引用，用户另选“转云端”才更新对应引用。对于 Typora 原生单图上传，仍由 Typora 按现有契约更新 URL，不能混淆。
- **下载本文全部图片**：解析远程图片并按当前文档已确认的目标位置处理；项目文件、全局图库、固定离线区、缓存已有匹配文件先复用。需项目独立副本时允许 `COPIED_EXISTING_LOCAL`（0 次网络下载）。否则才 `DOWNLOADED_NEW`。默认不改 Markdown。
- **检查并补齐双链**：先分析当前有效配置期望的本地/远程位置；已有位置仅更新索引，缺本地才在用户授权下下载/本地复制，缺远程才在用户授权下上传；两侧都有不传输。不存在被确认的物理本地副本时不得虚报 `DUAL_AVAILABLE`。
- **仅修复引用**：只选择已经验证的目标位置，显示前后 Markdown destination，用户确认才逐个精确更新；不能为了修复链接自动下载或上传，除非另有明确选择。

### D5.2 预检与执行

1. 先扫描当前文档的**引用实例**，按内容版本合并传输任务；同一 URL 的两处引用必须保留两份独立 Reference Identity 和 DOM Identity，不得始终命中第一张。
2. 预览列出：引用实例数、不同内容版本数、可直接复用数、实际待上传/下载数、项目副本数、拟建目录、目标仓库/分支/路径、预计字节数（若可取得）、拟改写引用数及失败原因；未验证数据明确标注“不确定”，不得虚报精确数。
3. **一键表示一键发起预检，不等于无需确认就批量改写**。展示“保留当前引用（默认）/转本地/转云端”互斥选择；确认操作范围后执行。运行前重新核验文件存在性、内容哈希、文档版本、目标权限、远程版本。
4. 执行中支持进度、取消、部分失败、失败重试、结果分类统计、任务级 singleflight。应重用 `ImageUploadService`、`ImageDownloadService`、`ImageAssetService`、`ImageTransferTaskStore`，不能另造一套上传器。
5. 结果必须如实分别统计：实际上传次数、实际网络下载次数、本地复制次数、复用已有次数、仅修改引用数、跳过和失败。明确显示“已有图片，直接复用（0 次上传/下载）”。
6. 引用修改必须保留 alt、图号、图名、相邻正文和正常 Ctrl+Z/Ctrl+Y；异步执行时如果文档内容已更改，终止或跳过失效引用，不以旧偏移覆盖新文本；不得调用全量重载破坏选择或撤销记录。
7. 同名不同内容不能覆盖，GitHub 403、网络异常、索引不完整不能当成资源不存在或“已存在”；原图 PNG→WebP 等版本转换若尚未实现，不得伪装成同 SHA 去重。

## D6. 智能提醒与用户授权（非常重要）

### D6.1 触发时机

- **普通打开文档、切换标签、浏览文档**：不得自动弹出全量向导或创建目录；仅显示轻量未检查/待处理状态。
- **首次明确启用当前文档的墨章图片管理**：可显示一次性引导，默认选“仅启用管理与索引”；用户可选“检查并补齐”，后续必须还有实际改动预览。
- **更改插入方式**：影响以后新图片的处理；**不得以此自动迁移历史图片或创建文件夹**。可显示简短说明，不默认弹批量确认。
- **改变历史链接偏好、双链目标、归档目录或启用自动补齐**：配置保存后可以只读检查既有资源差异，出现差异时提供轻量待处理提示；用户点击“立即补齐/应用到现有图片”才进入详细确认。
- **用户明确点击一键上传、下载、补链、修复引用**：必须展示预检和实际修改确认。
- **目标真实落盘目录不存在**：仅在本次已授权的操作确实需要写入该目录时提示是否创建；目录里无当前图片但可复用其他位置时优先复用；目录空且没有图片任务时不提示。
- **全局图库未初始化**：明确选择长期归档时，独立确认初始化与目标路径。仅填入图库路径不隐式创建图库标记，更不扫描其他目录。
- **有明显高风险（覆盖、删除唯一原件、跨仓库、无权限）**：额外阻断确认，不能用“记住本次选择”越权。

### D6.2 提示状态与抑制

引入或复用：`NOT_CHECKED`、`READY`、`ACTION_AVAILABLE`、`ACTION_REQUIRED`、`DEFERRED`、`APPLYING`、`PARTIAL`、`FAILED`。按“文档身份 + 有效配置版本 + 引用集合版本 + 提示类型”记录一次性引导和延后处理。配置、内容或资源状态发生实质变化时重新检查；切换标签不重复弹同一提示。允许安静/智能（默认）/主动提醒三档，不可采用每次切换文档强弹窗。

### D6.3 自动化授权边界

- L0 只读检查：可自动执行，避免高频全量扫描。
- L1 资产索引与已有位置登记：仅在模块启用范围内允许自动，不得修改 Markdown 或生成物理图库副本。
- L2 创建目录、实际上传/下载、复制、引用改写：仅在明确的批量确认或**事先专门授权的限定范围自动化策略**内执行，默认关闭。
- 自动同步分档：关闭（默认）/仅索引已有资产/明确授权的受限自动补齐；授权必须具体到操作类型、目标位置、仓库与是否允许改写引用，不得把“启用双链”当成授权全部传输。

## D7. 路径解析、资源缺失与文件夹泛滥防治

1. 区分 `./assets`（当前 Markdown 所在目录）、`./${filename}.assets`（文档专属路径）、全局图库、用户指定路径、上传暂存、可清理缓存、固定离线区，**不得自动叠加 `images` 子目录或再次嵌套项目文件夹**。
2. 只有需要落盘的操作才检查并选择创建目录；目录创建必须具体列入预览，使用规范化绝对路径进行边界、权限、安全验证，成功后原子写入、SHA-256 再核验，失败不覆盖原文件。
3. 用户设置 E 盘或其他全局图库后：图库不存在须弹出“初始化/更换目录/暂不处理”的明确选择；已存在则检查标记与实际内容，禁止覆盖用户数据。**配置图库位置不等于自动在每个 Markdown 旁创建图库**。
4. GitHub 已有同内容直接复用远程 URL，不得重复上传；本机已有同内容直接复用，确需项目可移植副本时可本地复制，但如实记录“0 次网络下载、1 次本地复制”。
5. 若配置了文件夹模式但当前文档已有历史其他目录引用：仅显示“可整理已有图片”，不能将“配置未落实”判为文档错误，也不能强制搬迁。
6. 图片 URL 已失效时优先定位已验证资源并提供“仅修复引用”；远程连接错误与真的 404/不存在须区分，避免不实补链。

## D8. 锁定与异步任务协同

1. 锁定只读检查不受影响；所有需要改写当前 Markdown 的批量转换、补链引用操作必须阻止并给出解锁提示，不能自动解除锁定。
2. 如果异步任务开始后用户锁定、切换文档或关闭文档，必须基于源文档 ID 和有效版本进行安全处置；绝不能将旧任务引用更新到新激活文档。
3. 已在进行的独立图库下载或上传可按任务政策完成，但不得未经新授权改写锁定文档。
4. 色块只表示文档检测结果；图片待处理状态只在面板内部显示，不污染诊断颜色定义。

## D9. 性能、DOM 安全与可访问性

1. 状态方块和管理中心位于独立插件 UI root，不能作为 `#write` 内图片段落、标题、表格或代码块的一部分；绝不将“上传本文图片”等菜单文字写进 Markdown。
2. 不使用高频 MutationObserver、重复轮询或每次鼠标移动全量扫描。文档切换、配置变更、任务状态变更采用有限事件通知、节流更新及明确销毁。
3. 弹窗/面板提供键盘可访问、焦点管理、Esc 关闭、点击外侧关闭、浅色/深色主题、窄窗口、滚动与 DPI 适配；不会同时叠加 Typora 原生右键菜单。
4. 清晰区分“正在检测、尚未检查、检查失败、文档无问题”；绿色仅表示检测完成且确实无错误与警告。

## D10. 测试与验收（不能以单测替代 GUI）

新增/完善单测与集成测试，至少覆盖：

- 绿/黄/红/灰状态优先级、锁定外框独立性；锁定后诊断色不改变。
- 状态方块展开/收起、Esc、点击外部、焦点、切文档、卸载和重复初始化。
- 文档检测数和原诊断列表一致、点击问题定位正确、重新检测并发不会产生重复扫描。
- 三级图片配置、全局模板不自动启用、指定文件夹规则、独立文档覆盖、同名文件隔离、未保存文档、重命名/移动。
- 六种 Typora 原生插入方式及配置失效/不可自动应用提示；不得用模拟测试宣称逐文档注入已通过真实 GUI。
- 首次启用引导一次、切换图链配置后仅轻提示、重复切文档不弹窗、状态变化后重新提醒。
- **无图片或仅检查/配置时，创建文件夹次数为 0**；本地项目 `assets`、`${filename}.assets` 和全局图库未初始化时都要验证。
- 用户明确确认一次批量任务后，按需创建**仅实际目标目录**，不在所有 MD 旁批量生成 `assets`。
- 批量上传 GitHub 已有内容返回 `REUSED_REMOTE` / 0 次上传；远程异名同内容复用，远程同名不同内容新建且不覆盖。
- 批量下载本地已有内容返回 `REUSED_LOCAL` / 0 次网络下载；图库存在但需项目独立副本返回 `COPIED_EXISTING_LOCAL`。
- 同一图片多处引用只传输一次，但每个 Reference Instance 正确定位；远程相同 URL 的两个 DOM 节点不能错误指向同一节点。
- 编辑锁定、文档切换、任务取消、重试、网络失败、Token 缺失、磁盘权限失败、目录同名冲突、异步文档变更。
- Markdown 内容前后比对，仅改写用户确认的 destination，保留正文/alt/图号/图名/撤销重做；插件菜单文字写入 Markdown 计数为 0。
- 不改动图片 V4.0 现有去重结果与上传 CLI 顺序、stderr/stdout 规则；不降低本地缺图和远程重复定位的测试覆盖门槛。

实际执行项目中可用的：`pnpm run typecheck`、定向 Vitest、全量 Vitest、`pnpm run build`、`node scripts/verify-image-privacy.mjs --all`；记录执行命令及真实结果。人工 GUI 清单必须包括：

- 右上角状态色块与锁定框（正常/警告/错误/未检查）。
- 打开/关闭面板、内容区滚动、切换多个文档、关闭重开。
- 一键上传/下载/补链预览、取消、确认、无授权目录不生成。
- Typora 原生图片插入六项、右键菜单、图片工具栏与正文隔离。
- R02 滚动激活/非激活，R03 侧栏拖拽，R04 窗口由小变大，R05 窗口由大变小。
- 保存重开、锁定状态恢复、浅色深色主题及不同 DPI。
