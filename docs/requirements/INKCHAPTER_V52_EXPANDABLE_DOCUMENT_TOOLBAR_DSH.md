## A2. 明确目标架构与 UI 状态机

最终组件名称建议：`ExpandableDocumentStatusToolbar`，不强制新文件名。**一套状态机，一处 DOM 宿主，三个功能标签，一个可切换内容区。** 逻辑状态拆开：

```ts
type Health = 'green' | 'yellow' | 'red' | 'gray';
type ToolbarMode = 'collapsed' | 'expanded';
type TabId = 'diagnostics' | 'images' | 'lock';
type DetailView = 'summary' | 'diagnostic-details' | 'image-preview' | 'batch-progress';
```

不得将锁定状态混到 Health 颜色；灰色用于未检查/不可用/检测中等非健康结论；错误优先于警告，未获得可靠检测结果不得冒充绿色。

绑定当前活动 Markdown 的稳定身份及 epoch/generation，旧文档异步诊断或图片摘要不得覆盖新文档。文档切换默认收起横向栏，切到新文档更新色块；未保存文档要有安全身份处理。组件与右下角导航器的刷新和异常边界相互独立。

## U1. 完全移除默认方块的外部白色圆角按钮框

**这是用户本轮新增的强制外观要求，不可忽略。**

1. 收起后只显示一个 12–14px 的红/黄/绿/灰**纯色小方块**，圆角约 2px；无常驻白色圆角大按钮、无阴影、无外围背景、无装饰边框。
2. 保留约 32–36px 的透明点击热区与语义化按钮/可访问名称，但热区必须 `background: transparent`、无常驻 `box-shadow`、无常驻 `border`、无浏览器默认按钮外观。禁止为了美化将热区缩成 14px 导致不好点击。
3. 鼠标 hover 用轻微亮度/透明度变化，不能又冒出一层白色按钮外壳；激活/展开状态不得恢复旧白框。
4. **只有文档真正处于锁定状态**，在色块外约 3px 增加 1–1.5px 中性色**细线方形轮廓**，避免厚重圆角框；锁定标记不改变三色诊断颜色。
5. `:focus-visible` 必须有可识别且与锁定外框区分的键盘焦点样式；可考虑焦点轮廓偏移、虚实线区别；不能将焦点误认为锁定。
6. 浅色/深色主题与 DPI 100%、125%、150% 下尺寸、对比度、边缘清晰，不使用主题不兼容的强制白底。
7. 不引入新的长期常驻数量数字、“编辑”按钮或锁图标；统计信息在 tooltip 与内容区显示。

## U2. 单击向左展开、双击快捷锁定（必须手势仲裁）

目标：**右侧小方块永远锚定同一位置**。左键单击后，检测/图片/锁定三个横向标签从右向左展开，动画结束后在标签栏正下方显示**同一个紧凑内容区**。再次单击收起。初次展开默认“检测”。

- 标签栏宽约 210–250px；内容区宽约 300–340px（以实际可视窗口自适应），不得推动正文重新排版，不碰窗口系统控制按钮。
- 向左展开动画 160–220ms；内容出现和标签切换约 80–150ms。使用安全的 width/clip/opacity/transform 与右端固定锚点，**不能横向压缩文字**，不要因动画导致布局抖动；支持 `prefers-reduced-motion`。
- **双击状态方块切换锁定/解锁**，并且必须彻底解决 `click` 与 `dblclick` 导致的“展开 → 收起 → 锁定”闪烁及误触发；采用一个手势仲裁器。两个连续点击被判双击时，只执行一次锁定变更，不执行单击展开/收起；正常单击操作延迟保持可用，提供锁定标签按钮和键盘入口作为不依赖双击的替代方式。
- 双击锁定必须调用**现有真实文档编辑保护**逻辑；如果失败不能只增加线框骗用户已锁定。异步锁定中禁用重复操作、完成后更新实际状态，失败显示简洁原因并保留旧状态。
- 关闭机制：再次单击色块、Esc、点击外部、切换文档；避免鼠标从色块移动到标签区域时误关闭。
- 焦点可通过 Tab 到达状态按钮、标签、内部操作；Enter/Space 行为明确；关闭后焦点合理恢复。
- 禁止在每次打开时重复绑定全局监听器，销毁时释放；不得插入 `#write`。

## U3. 三个标签与一个内容区（禁止再开第二层浮窗）

横向栏只提供三个主标签，顺序固定为：**检测（默认）｜图片｜锁定**。每次仅显示当前标签内容；只有一个内容承载容器和一个 DOM 管理实例，不要制造三套同时挂载的悬浮面板。主视图里不要重复冗长文件名、标题、状态文字、大块黄色提示和多层卡片。

### U3.1 检测标签

- 默认紧凑摘要：`13 错误 · 2 警告` 类信息、`重新检测`、`详情`；统计值来自真实现有诊断结果，未检查显示真实未知。
- 点击 `详情` **在同一容器内部切换视图**，显示可滚动诊断列表；**严禁额外弹出旧诊断浮窗并与工具栏叠加**。
- 保持原诊断规则、严重程度和定位信息；点击条目时可关闭内容区后定位文档，避免遮挡目标正文；原有定位、修复/建议入口不能悄悄失效。
- 诊断详情可独立滚动，最大高度受窗口约束；不复制长篇重复说明。
- `重新检测` 只发起已有诊断刷新，不能无意修改 Markdown，也不能影响导航器。

### U3.2 图片标签

- 展示当前文档图片配置**作用范围来源**（全局默认 / 继承文件夹 / 文档级覆盖）、实际插入方式、自动同步状态；图片管理未启用时只显示一行状态和 `配置当前文档`，**不显示大块黄色提示**。
- 完整沿用 Typora 原生六种插入方式：无特殊操作、复制到当前文件夹、复制到 `./assets`、复制到 `./${filename}.assets`、上传图片、复制到指定路径；这里仅展示当前生效选项，复杂编辑进入完整设置，不另造第七种模式。
- 已启用时紧凑提供：`上传本文图片`、`下载本文图片`、`检查并补齐双链`、`当前文档高级设置`。按钮必须接入既有服务，不能是空入口。
- 批量操作保持 `预检 → 实际内容去重/资产复用 → 展示拟建目录与传输/引用变更 → 明确确认 → 执行 → 结果汇总`；默认不修改 Markdown。对未实现的引用改写二次授权必须如实标注，不能伪报“补链完成”。
- 从 E 盘图库或项目图库复用已有文件时要区分 0 次网络下载与本地复制；GitHub 无法验证不能当作已存在。
- 只打开图片标签、调整设置、查看索引/预检不得新建 `assets`、`${filename}.assets` 或全局图库目录；需要真实写入时先确认目标、目录及授权。
- 当前文档锁定时，需修改 Markdown 的引用转换入口明确阻止或要求先解锁；只读检查可用。

### U3.3 锁定标签

- 一行状态 + 一键锁定/解锁，必要时一句极短说明；不显示大块表单。
- 文档锁定状态取自**真实锁定控制器**，不可由按钮本地布尔变量代替；双击状态方块与锁定标签必须使用同一动作入口和一致的成功/失败反馈。
- 锁定后仍可查看诊断与图片状态，不得未经解锁自动修改文档内容。

## P1. 生命周期、性能、主题和导航器隔离

- 状态色刷新、文档图片摘要异步查询、诊断和锁定都必须做文档身份与 epoch 核对，不能跨文档污染。
- 文档切换后默认收起工具栏，新文档色块根据新文档状态恢复；不保留旧文档检测列表。
- UI 渲染失败应记录错误并隔离自身，不允许使右下角导航器、诊断、几何计算整条管线停止；不得以完全吞错掩盖测试失败。
- 右下角导航器：只在真实可纵向滚动的活动文档显示，短文档隐藏；长↔短↔长切换、DPI/窗口 resize 后仍正确。容器显示与方向按钮 enabled 分离，活动文档短暂切换态不应让长文档永久消失。
- 浮层定位不受编辑器滚动、文件树拖拽和窗口宽度变化影响；不会挡住窗口关闭控件，窗口不足时合理收缩、内容区内部滚动。
- 不用高频 MutationObserver、周期轮询、大量 DOM 重建实现稳定性；必要监听器尽可能复用并限制刷新频率。
- 浅色/深色主题、Windows 100/125/150% DPI、自适应窗口；UI 与 `#write` 隔离，始终不被 Markdown 保存。

## T1. 必须增补/修复的自动化测试

逐项增加或更新测试，禁止降低已有覆盖门槛：

1. 纯色状态块无常驻白色圆角外壳、阴影、背景、装饰边框；透明热区尺寸与键盘焦点明确。
2. 绿/黄/红/灰映射、错误优先级、未检查不冒充健康。
3. 已锁定时仅添加细外框且颜色不变，解锁去框；焦点不触发“已锁定”状态。
4. 单击展开、再次单击收起；双击只执行一次锁定，不触发先展开再收起。
5. 触发失败锁定不可假显示为已锁；真实锁定控制与标签状态同步。
6. 默认“检测”标签；切换检测/图片/锁定只更新一个内容区。
7. 检测“详情”不调用旧浮窗；诊断项定位可用，列表滚动不越界。
8. 图片未启用时只显示压缩单行状态，已启用时按钮具备真实回调与正确禁用原因。
9. 图片上传/下载/补链预检不落盘；拒绝确认不传输；确认后沿用 V4.0 SHA-256 去重结果。
10. 图片配置全局/文件夹/文档覆盖来源准确，切文档异步数据不串。
11. Esc/外部点击/文档切换关闭，销毁时释放事件监听，无重复 DOM。
