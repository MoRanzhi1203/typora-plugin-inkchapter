# Document Utilities（文档检测 / 编辑锁定 / 滚动导航）

> 本页整合 Phase 7R.3.10–7R.3.11.8B.11 与 UI Phase 1/2B/2C（git 提交证据：`01e09c4`→`212481d`→`37c14f3`，HEAD=`37c14f3`）的耐久结论。目标是：**UI/诊断/滚动全部消费既有 canonical authority，绝不重建编号语义；身份即正确性；事件驱动反轮询；真实 Runtime 是唯一验收**。凡"真实 Typora 视觉/人工验收"尚未执行之处，本文一律如实标注 PENDING（禁止以 TSC/VITEST/单元测试替代）。

## §1 总体架构

- **单例 `DocumentUtilityOverlayHost`**（mount / bindDocument / dispose），共享 document context（documentKey、active editor root、active scroll container、canonical authorities）。
- **非侵入契约**：overlay 挂在 `body`，不进 `#write` 业务内容、不进导出/复制/打印/保存；utility 自身 mutation 不得进入编号语义管线（`UTILITY_UI_MUTATION_CAPTION_RECONCILE/HEADING_RECOMPUTE/FORMULA_RECONCILE_COUNT=0`）。
- **锚定真实 editor shell/viewport**（非整个 Electron 窗口；DevTools/侧栏可改视口）。
- **Authority-driven，禁止 polling**：诊断/几何/滚动/日志 summary 全部事件驱动 + coalesced rAF / 有限 quiescence；`setInterval` 全面禁止。

## §2 UI 几何与 selector 契约

- **TREE OWNERSHIP ≠ ROOT LAYOUT AUTHORITY**：
  - `data-inkchapter-ui-root="document-utilities"` = ownership marker，只用于 mutation 过滤/forensic，**禁止携带任何 viewport 几何**。
  - 唯一 `data-inkchapter-utility-root="true"` 拥有 viewport portal 几何（full-viewport fixed：`inset:0;100vw;100vh;pointer-events:none`），选择器必须只匹配一个元素（`ROOT_VIEWPORT_GEOMETRY_MATCH_COUNT=1`）。
  - 编译后 CSS 硬门禁：ownership selector 不得含 viewport geometry（`OWNERSHIP_SELECTOR_FREE_OF_VIEWPORT_GEOMETRY`）。
- **子元素尺寸契约**：toolbar `width:max-content`；navigator ≤96×220px；按钮高 24–48px；drawer `clamp(320px,28vw,420px)`；toast max-content；禁 100vw/100vh/inset:0/stretch 类规则。
- **指针事件契约**：root `pointer-events:none`，toolbar/navigator/drawer `auto`；z-index 最小充分（禁 2147483647）。
- **矩形权威命名**：`writeRect / editorShellRect / scrollViewportRect / overlayRootRect / toolbarRect / navigatorRect / drawerRect`；toolbar 可超出 writeRect 用右侧留白，但必须在 editorShellRect 内。
- **遮挡指标**：分母用 `visibleWriteRect = intersection(writeRect, scrollViewportRect)`；`TOOLBAR/NAVIGATOR_WRITE_OCCLUSION_RATIO < 0.10`。
- **Drawer/Navigator 布局（状态-几何事务 + 独立 anchor，7R.3.11.8B.3）**：
  - 单一 Drawer state authority：`setDrawerOpen(nextOpen, reason)` 唯一入口；drawer 方法**禁止直接写 `navigator.style.right/left/transform`**（`NAVIGATOR_POSITION_WRITE_SITE_COUNT=1`）。
  - geometry execution 读**实时** `this.drawerOpen`；`pendingGeometryReasons: Set` 保留全部 reason（同帧合并不丢语义）。
  - **Navigator 位置 authority = viewport/editorShell/overlayRoot**，与 Drawer 各自独立 overlay anchor：`navigatorRight = innerWidth - shellRect.right + NAV_RIGHT_GAP`（≈29px）；**禁止**用 `drawerWidth/drawerVisible/drawerItemCount/drawerRect` 参与 navigator 定位（旧语义"open = 上式 + DRAWER_RIGHT_GAP + drawerWidth + DRAWER_NAV_GAP"已废弃）。drawer open/close 前后 `deltaX/deltaY <= 1px`（`NAVIGATOR_POSITION_STABLE_WITH_DRAWER`）；`DRAWER_NAV_INTERSECTION_AREA=0`。纵向空间冲突**只允许 Drawer 达到 max-height 后内部滚动**，禁止横向推 Navigator。
  - geometry equality/NO_OP 判定**必须包含 navigatorRight**。
  - BCR 在 geometry commit 之后采集（`drawer-open/close-committed`）。
  - `DOCUMENT-UTILITY-NAV-PLACEMENT`：仅当 `navigatorExpectedVisible=true` 才计算 `expectedRight/actualRight/rightDelta`，PASS 以 delta≤1px 为准（>1px 由 FAIL invariant `NAVIGATOR_POSITION_DRIFT` 承接，判定容差 `NAV_POSITION_TOLERANCE_PX`=1~2px，见 §5）；`navigatorExpectedVisible=false` 时一律 `decision=NOT_EVALUATED / reason=NAVIGATOR_EXPECTED_HIDDEN`（不得再产假 POSITION_DRIFT）。
- **BCR verdict**：pre-layout 必须 `GEOMETRY_PENDING`，first geometry commit 后才 `VISIBLE_GEOMETRY`（MOUNTED→PENDING→FIRST_COMMIT→VISIBLE，`geometryCommitted` 标志）；`isAccidentalFullscreenChild`（≥80% viewport）检测。BCR 必须区分**合法隐藏**与**未就绪**：`navigatorExpectedVisible=false` 且 navigatorRect=0x0 → `navigatorState=EXPECTED_HIDDEN`（**不是** `GEOMETRY_PENDING`）；只有 `navigatorExpectedVisible=true` 且 rect=0x0 才允许 `GEOMETRY_PENDING/NAVIGATOR_MISSING`。整体 BCR 不得因 navigator 合法隐藏而整段 pending。

### Visible Editor Geometry 双几何模型（Phase 2-B.2）

- **`editorLayoutWidth`（编辑器内部布局宽度，受 workspace min-width 影响，可 > 屏幕）≠ `editorVisibleWidth`（真实可见宽度，viewport clip 后）**。核心原则："内部布局可以比屏幕宽，Overlay UI 只能相信用户真正看得见的区域"。
- Toolbar/定位等 overlay 元素只消费 `visibleWidth` + 二级 containment 保险 `isRectHorizontallyContained`（anchored to `visibleEditorRect`），禁止用 `editorLayoutWidth` 直接定位 overlay。
- 新增纯函数 `intersectRects / computeVisibleHorizontalRect` 与 `DocumentUtilityGeometrySnapshot`；日志语义区分 `writeLayoutRect / writeVisibleRect`。
- **`DOCUMENT-UTILITY-VISIBLE-EDITOR-INVARIANT`**：`ZERO_VISIBLE_EDITOR_BUT_TOOLBAR_VISIBLE`、`TOOLBAR_ESCAPED_VISIBLE_EDITOR` 均判 FAIL。

### Document Workspace Min-Width Guard（7R.3.11.8B.6）

- 保护对象是 **Document Workspace / Editor Viewport 承载层**（`DOCUMENT_WORKSPACE_MIN_WIDTH`，初始验证值 ≈520px，须按 480/500/520/540/560 矩阵实测后定值），**不是** `#write` 固定纸宽——`WRITE_FIXED_WIDTH=false`、`WRITE_THEME_WIDTH_PRESERVED`（正文继续遵守 theme max-width/margin/padding）。
- 禁止：`#write { width/min-width: 520px }` 一类硬写；`white-space/word-break/font-size/transform/zoom` 掩盖；自动关闭用户 sidebar；给所有祖先逐层写 min-width（只修 FIRST_FAILING_LAYER）。
- **Toolbar / Drawer / Navigator 均不得进入正文 flex**（`TOOLBAR_REDUCES_DOCUMENT_WIDTH=false / DRAWER_REDUCES_WORKSPACE_WIDTH=false / NAVIGATOR_REDUCES_WORKSPACE_WIDTH=false`）；Drawer 打开前后 workspace width delta≤1px。
- 状态模型 `NORMAL / COMPACT / MIN_WIDTH_GUARD`（normalThreshold≈700px 亦为实测值）；状态写 **read→derive→仅状态/token 变化时写**（ResizeObserver 回调可多次，但 state write 只在 threshold crossing 发生，防 feedback loop）。
- 极窄窗口（如 480/400px）进入 MIN_WIDTH_GUARD 时允许外层受控横向 overflow/clipping，但正文不得 collapse 到不可读宽度；横向 overflow 必须稳定（`HORIZONTAL_OVERFLOW_STABLE`，禁 scrollWidth 累加/漂移）。
- audit：`DOCUMENT-UTILITY-WORKSPACE-WIDTH-INVARIANT`（`FAIL_WORKSPACE_BELOW_MIN/FAIL_DRAWER_REDUCED_WORKSPACE/FAIL_NAVIGATOR_REDUCED_WORKSPACE/FAIL_EXTREME_WRAP/FAIL_LAYOUT_FEEDBACK_LOOP`）+ `DOCUMENT-UTILITY-WORKSPACE-WIDTH-STATE`（仅 transition：NORMAL↔COMPACT↔MIN_WIDTH_GUARD，含 window/sidebar/requested/effective/minWidth）。

### Toolbar 三态密度 full / compact / suppressed（UI Phase 2-B.1）

- 单一纯决策 `decideToolbarDensity/presentation` + 唯一 DOM writer `apply`；suppressed 时 `hidden=true` 但 DOM **常驻单实例**（`toolbarCount=1 / DUPLICATE_MOUNT_GATE`）。

- `UNKNOWN_GEOMETRY ≠ KNOWN_COLLAPSED`：jsdom/几何不可用不得隐藏 toolbar，只有已知超窄才 suppressed。

## §3 Document Diagnostics（文档检测）

- **单一 authority**：`DocumentDiagnosticsAuthority` 持有**每个活动文档一份已提交 snapshot**；`computeDocumentDiagnostics` 纯函数消费既有 canonical facts，UI（drawer/toolbar）只读 snapshot，绝不复制 validator 逻辑。
- **Snapshot 身份契约**：`documentKey + revision + sourceRevision + generatedAt + diagnostics + errorCount + warningCount + infoCount`；内容指纹去重发布（同文档同内容不 re-notify）。自 8B.7.1 起 **effectiveMode/effectiveModeRevision/severity 语义指纹必须纳入 snapshot 与 fingerprint**——`content unchanged + effective mode changed = diagnostics semantics changed = 必须重新计算并发布新 immutable snapshot`；`snapshotMode == effectiveMode == diagnosticsMode`，否则 `FAIL_STALE_DIAGNOSTIC_SNAPSHOT`。
- **Stale 防线**：`snapshot.documentKey == activeDocumentKey` 才发布/渲染；不一致 → DISCARDED（不显示上一文档瞬时内容）；Drawer 切文档时保持打开并原位刷新（`KEEP_DRAWER_OPEN_ON_DOCUMENT_SWITCH=true`）。8B.7.1：mode transition（`HEADING_STRUCTURE_EFFECTIVE_CHANGED` 单事件，含 documentKey/before/after/effectiveModeRevision/source）驱动一次有界重算，单事务**最多一次** publish（`ONE_MODE_TRANSACTION_MAX_DIAGNOSTIC_PUBLISH_COUNT=1`）；幂等 mode 写入（loose→loose）不 rebuild；dirty draft ≠ effective（未保存不 rebuild）；global 变更只在 effective 改变时 rebuild（override shield 时 `GLOBAL_CHANGE_WITH_SHIELDED_OVERRIDE_DIAGNOSTIC_REBUILD=0`）；重算前 capture（documentKey/documentRevision/canonicalRevision/effectiveMode/effectiveModeRevision），完成后复验，document switch/rapid toggle 的 stale 结果一律 discard（`STALE_DOCUMENT_DIAGNOSTIC_PUBLISH_COUNT=0`）。
- **诊断模型**：severity(category)/code/message/stableIdentity/targetIdentity/metadata/locator；ERROR=已证明无效/投影失败；WARNING=可疑不完整；INFO=统计；**空文档≠错误**（区分 no-doc/empty/invalid）。
- **实时触发**：document open/switch、heading snapshot committed（`onCanonicalFrameCommit`）、strict/loose mode change（`onSettingsChanged`）、`#write` MutationObserver（rAF 合并，禁逐 keydown 全文 parse）；全为事件驱动。**Toolbar/Drawer 只订阅已发布 snapshot**（`toolbarObservedDiagnosticRevision == drawerObservedDiagnosticRevision == publishedSnapshotRevision`；drawer 打开时原位替换、不得持有 open-time 拷贝）；手动"重新检查"保留但只是 `requestDiagnosticRecompute(reason)` 之一（MANUAL_RECHECK/DOCUMENT_MUTATION/DOCUMENT_SWITCH/HEADING_STRUCTURE_MODE_CHANGED/CANONICAL_FRAME_CHANGED），不是 mode sync 的必要步骤。
- 审计：`DOCUMENT-UTILITY-DIAGNOSTIC-SNAPSHOT`（action=PUBLISHED + effectiveMode/effectiveModeRevision/fingerprint）+ 可选 `DOCUMENT-DIAGNOSTIC-SNAPSHOT-DIFF`（仅 mode transition：addedRuleIds/removedRuleIds/severityChangedCount/locationChangedCount）。

### 规则集

| ruleId | severity | authority | 说明 |
|---|---|---|---|
| `STRICT-FIRST-H1` | error | raw Markdown source + canonical frame | 文档首物理位置必须直接是 H1；**仅 strict 规则激活时评估**（strictMode && !plainBodyOnly）；定位到该 H1 自身（canonical-node/source-range），非 document-start |
| `STRICT-SINGLE-H1` | error | canonical heading frame `semanticState.physicalLevel===1` | strict 下全文必须且只能一个 H1；h1Count=0 → `STRICT_SINGLE_H1_NO_H1`（reason=NO_H1）；>1 → `STRICT_SINGLE_H1_MULTIPLE_H1`（reason=MULTIPLE_H1，multi-target 定位第二个及之后 H1）；非 strict/纯正文豁免 → SKIP |
| `HEADING_LEVEL_GAP` | strict=ERROR / loose=WARNING | canonical heading sequence | **只报前进跳级**（nextLevel > previousLevel+1 → missingLevels），回退不报（H4→H2/H6→H1=PASS）；generic 结构诊断，**与 policy 激活无关**，有真实标题即检查 |
| `EMPTY_HEADING` | strict=ERROR / loose=WARNING | canonical entry 存在 | 仅当 `CanonicalHeadingEntry` 存在且 `normalizedText.trim()===''`；普通文本 `##` 不是 EMPTY_HEADING |
| `PLAIN_TEXT_HEADING_MARKER` | IGNORE（默认 disabled） | — | 普通文本行首 hash marker 的结构态名；默认不产 ERROR/WARNING；未来若启用只能 HINT，绝不参与结构 |
| `LATENT_ATX_HEADING_MARKER` | strict=WARNING / loose=HINT | raw Markdown source（source-syntax，隔离） | raw 行首 1–6 个未转义 `#` 且无对应 canonical entry；禁止写入结构/编号/outline/caption/formula scope |
| `DOCUMENT_TERMINAL_NEWLINE_MISSING` | warning（全 mode） | raw/serialized source | 文件不以 `\n`/`\r\n` 结束；文案"文档末尾缺少换行符"；location=document-end（GO_BOTTOM） |
| `DOCUMENT_TRAILING_BLANK_LINES_EXCESSIVE` | warning（全 mode） | raw/serialized source | terminal newline 之后额外空行 ≥2；文案"文档末尾存在过多空行"；location=document-end |
| `FIGURE/TABLE/CODE_MISSING_NAME`、`CODE_BLOCK_MISSING_LANGUAGE` 等命名/元数据 | warning | ObjectCaptionState / block metadata | 名称判定 = `semanticName.trim().length>0`（type+number≠name） |
| 本地资源缺失（`LOCAL_LINK_TARGET_NOT_FOUND`） | warning | dirname(当前 md) 为 base 的文件系统 truth | HTTP/HTTPS 不进 missing；source token 未改不得判 STALE |

旧 EOF 语义正式废弃（历史迭代仅作归因）：旧码 `DOCUMENT_TRAILING_BLANK_LINE / DOCUMENT_TRAILING_BLANK_LINE_MISSING` 与"文末必须**至少**一个空行"，中间态为"恰好 1 空行"与"1~2 通过、≥3 过多"，最终收敛为现行 **standard terminal-newline**：无 terminal newline→`DOCUMENT_TERMINAL_NEWLINE_MISSING`；0 或 1 个额外尾部空行→PASS；≥2→`DOCUMENT_TRAILING_BLANK_LINES_EXCESSIVE`。EOF authority = serialized source（`getMarkdown()`），与 Live Editor 视觉空白 paragraph 完全解耦（不再要求视觉空行，Table/Code/Figure/Formula 结尾以 source 正常 `\n` 结束即 PASS）。off-by-one 定义：`正文\n`→0 个额外空行、`正文\n\n`→1、`正文\n\n\n`→2（CRLF 等价；空白行=整行 trim 空）。文件级 reconcile 支持 added/retained/removed，sourceRevision 为 authority；audit `[DOCUMENT-TRAILING-BLANK-AUDIT]`（含 hasTerminalNewline/extraTrailingBlankLineCount/policyDecision/previous/next/diff/publishDecision）。

### STRICT-SINGLE-H1 的 authority bridge（7R.3.11.8B.1）

- canonical heading level 真实字段 = **`entry.semanticState.physicalLevel`**（`CanonicalHeadingFrame` 生产类型），禁止伪造扁平 `entry.physicalLevel`。
- 唯一 normalization boundary：`mapCanonicalHeadingFrameForDiagnostics(frame, activeDocumentKey)` → `WAIT(FRAME_NOT_READY|DOCUMENT_MISMATCH) / INVALID(PHYSICAL_LEVEL_MISSING|OUT_OF_RANGE|ENTRY_SHAPE_INVALID) / READY(headings, h1Facts)`。
- **fail-closed**：frame=null → WAIT（不报 NO_H1）；frame ready 且 canonicalEntryCount=0 且 shape 有效 → 才允许 `READY/h1Count=0`（strict 下 NO_H1）；有 entries 但 level 缺失/越界 → INVALID → STRICT-SINGLE-H1 不评估、popup=0；**绝不允许 INVALID→[]→NO_H1**。
- **文档身份守卫**：`frameDocumentKey == activeDocumentKey`，否则 `WAIT_DOCUMENT_TRANSITION`。
- DOM `h1` count 只作 forensic cross-check（`domH1Count`），不得替代 canonical authority。
- 审计：`DOCUMENT-UTILITY-H1-AUTHORITY-BRIDGE`（physicalLevels/h1Count/invalidEntryCount）+ `DOCUMENT-UTILITY-H1-AUTHORITY-INVARIANT`（READY 且 physicalLevels 含 1 但 h1Count=0 → FAIL 并阻止发布 false NO_H1）。
- 测试必须引用真实生产 `CanonicalHeadingEntry` shape（`satisfies` 或官方 factory），禁止 synthetic flat mock 掩盖 shape drift。

### 标题结构 authority：canonical-only 三态 + source-syntax 隔离（7R.3.11.8B.4 / 8B.4.1）

- **唯一结构权威 = `CanonicalHeadingFrame.entries`**。只有 canonical heading node 可参与结构检测（标题层级/strict H1/章节边界/outline/caption scope/formula scope/编号/结构诊断）；禁止用 raw Markdown regex / `querySelectorAll('h1..h6')` / outline DOM / 渲染编号文本 / 普通 paragraph 重建"标题"。
- 行首 `#` 文本三态（非结构标题）：`STRUCTURAL_HEADING`（canonical entry 存在，可参与结构）、`EMPTY_HEADING`（canonical entry 存在且 `normalizedHeadingText.trim()===''`）、`PLAIN_TEXT_HEADING_MARKER`（raw 行首 1–6 个 `#` 但**无 canonical entry**，不得当作 H1/H2/H4，不产 EMPTY_HEADING/GAP/STRICT-SINGLE-H1/边界/caption/formula 效应）。
- **Heading Gap**：只检查 canonical sequence；`nextLevel > previousLevel + 1` → GAP（missingLevels 精确列出，如 H3→H6 missing=[4,5]）；**回退不是 gap**（H4→H2、H6→H1、H5→H3 = PASS）。Gap 定位到 **offending heading**（造成跳级的下一个标题，如 H2→H4 定位 H4），不定位上一级。
- **结构诊断（Structural Diagnostics）与源码语法诊断（Source Syntax Diagnostics）两套隔离 authority**：
  - Structural = `STRICT-FIRST-H1/STRICT-SINGLE-H1/HEADING_LEVEL_GAP/EMPTY_HEADING`，只消费 canonical entries；
  - Source Syntax = `DOCUMENT_TERMINAL_NEWLINE_MISSING/DOCUMENT_TRAILING_BLANK_LINES_EXCESSIVE/LATENT_ATX_HEADING_MARKER`，可读 raw source，但**禁止写回** canonicalHeadingCount/diagnosticHeadingCount/h1Count/boundaryCount/chapterOrdinal/outline/caption scope/formula scope。
  - 四态语义：`ESCAPED_LITERAL`（`\#`…，IGNORE，结构效应=0）、`LATENT_ATX_HEADING_MARKER`（未转义且无 canonical entry；strict=WARNING/loose=HINT）、`CANONICAL_EMPTY_HEADING`（ERROR/WARNING）、`CANONICAL_NORMAL_HEADING`（按结构规则）。detector 必须对齐 Typora 真实 parser（fixture：`#`/`##`/`#text`/`# text`/`\#`/前导空格/`#######` 的解析结论），不得自造 CommonMark 方言。
  - **同一 source/target 上 latent 与 canonical 状态互斥迁移、禁止双报**：latent 行转成真实 heading → latent 消失、由 EMPTY_HEADING/GAP 接管；canonical heading 退化为普通 `##` → EMPTY/GAP 解除、latent 可重新出现。
  - AutoFix 只预留 `fixable=true / fixKind=ESCAPE_HEADING_MARKER`，**不实现写入**（不扩大编辑/锁定语义）。
  - audit：`DOCUMENT-UTILITY-DIAGNOSTIC-AUTHORITY-SEPARATION`（canonicalHeadingCount==structuralHeadingCount、latentAtxCount、nonCanonicalStructuralIncludedCount=0）、`DOCUMENT-UTILITY-LATENT-ATX-MARKER`（line/column/markerLevel/escaped/canonicalMatch/mode/severity，仅 transition）、`DOCUMENT-UTILITY-HEADING-DIAGNOSTIC-AUTHORITY`/`-INVARIANT`（canonical vs diagnostic count、nonCanonicalIncludedCount→FAIL 阻止错误 gap publish）。

### Severity policy（统一 DocumentDiagnosticSeverityPolicy）

- **validator 不得写死 severity**：统一入口输入 `ruleId + documentMode + violationReason` → ERROR/WARNING/HINT/IGNORE。severity 是**独立 policy**，与 location policy、rule authority 分离（同一 rule strict/loose 只变 severity，不得复制两套 validator/locator）。
- 现行映射：`HEADING_LEVEL_GAP` strict=ERROR/loose=WARNING；`EMPTY_HEADING` strict=ERROR/loose=WARNING；`LATENT_ATX_HEADING_MARKER` strict=WARNING/loose=HINT；`ESCAPED_LITERAL`=IGNORE；`PLAIN_TEXT_HEADING_MARKER`=IGNORE（默认）；命名/格式类（code/table missing name、missing language、EOF 类）全 mode=WARNING。
- Drawer 计数（errorCount/warningCount/hintCount）必须来自统一 snapshot 且随 mode 切换实时刷新；audit `DOCUMENT-UTILITY-DIAGNOSTIC-SEVERITY`（仅 transition：ruleId/mode/previousSeverity/nextSeverity）。

### strict 标题政策激活与豁免（7R.3.11.8B.9 / 8B.10 / 8B.11）

- **`storedMode = 'strict'` 绝不等于 `strictPolicyActive = true`**。政策权威链（分层）：`stored settings → global heading config → feature activation → scope activation → effective heading policy for current document → diagnostics strict rules`。
- 有效政策模型 `EffectiveHeadingPolicy{ active, mode: 'strict'|'loose'|'custom'|null, activationSource: 'none'|'global-explicit'|'document-explicit'|'inherited', strictRequireSingleH1?, documentKey }`；`strictPolicyActive = active && effectiveMode==='strict'`（实现见 `heading-policy-activation.ts`）。禁止把"settings 对象存在/mode 非空/typeof==='object'"当 configured（默认初始化会让这些恒真）；unconfigured 不得回退 strict（禁 `mode ?? "strict"`）。
- **三段门**：`headingFeatureEnabled && headingPolicyConfigured && mode==='strict'` 才允许产 strict 专属诊断；未激活/未配置时 `STRICT_SINGLE_H1 / STRICT_FIRST_H1 / PRE_H1_BODY / STRICT_ZERO_H1 = SKIP`（即使 h1Count=0 或多 H1）。
- **generic 结构诊断与 policy 无关仍需产出**：跳级等真实标题结构问题在 policy 未启用时继续报（**禁止 `if (!headingFeatureEnabled) return []`** 一刀切关闭所有 heading diagnostics）；loose/custom 不得误用 strict H1 约束，custom 按自身契约、禁止 fallback strict。
- **唯一内容级豁免 plainBodyOnly**：`plainBodyOnly = headingCount(canonical H1..H6)===0 && hasMeaningfulBodyContent===true`。此时允许"无 H1"（strict 下 SKIP 顶层须 H1/H1 唯一/H1 前无正文一组）；**空文档不豁免**（headingCount=0 且无 meaningful body → 行为保持既有，不因本规则扩展）。`hasMeaningfulBodyContent` 必须用真实文档内容语义（禁 `source.trim()>0` 后把 HTML 注释/空白/插件 metadata/隐藏 marker/caption decoration 当正文）。
- **一旦出现任何 heading（含 H2..H6）立即恢复全部 strict 契约**：文档选择标题结构后必须顶层为 H1、H1 唯一、H1 前无正文、首标题不得低于 H1、层级不跳级；`strictHeadingRulesActive = strictMode && !plainBodyOnly`（实现见 `document-diagnostics.ts`）。live transition（纯正文→首个 H1→第二个 H1→删光标题回纯正文）必须实时自动更新，禁止依赖"重新检查"。
- audit：`[HEADING-POLICY-DIAGNOSTIC-AUDIT]`（storedMode/featureEnabled/configured/strictPolicyActive/h1Count/diagnosticCode/decision=EMIT|SKIP/reason=STRICT_POLICY_INACTIVE…）、`[HEADING-POLICY-AUTHORITY-AUDIT]`（activationSource/effectivePolicyActive/effectiveMode/effectiveStrictRequire）、`[STRICT-HEADING-SHAPE-AUDIT]`（headingCount 按 H1..H6 分列/hasMeaningfulBodyContent/plainBodyOnly/firstMeaningfulBlockKind/hasBodyBeforeFirstH1/strictRuleSetDecision=PLAIN_BODY_EXCEPTION|ENFORCE）。

### 定位（locator）

- **契约 `PUBLISHED_DIAGNOSTIC => LOCATABLE_DIAGNOSTIC`**：published diagnostic 带 `location = null` 不再合法；`diagnosticCount == locatableDiagnosticCount`、`unlocatableDiagnosticCount = 0`（audit `DOCUMENT-DIAGNOSTIC-LOCATION-CONTRACT`）。同时 `diagnosticCount == errorCount+warningCount+hintCount`（audit `DOCUMENT-DIAGNOSTIC-RULE-SNAPSHOT`，仅 fingerprint 变化时输出）。
- 统一入口 `resolveDiagnosticLocation(diagnostic, currentDocumentContext)` + 动作入口 `locateDiagnostic(diagnosticId)`（overlay 所有"定位"按钮一律走它，禁止各写一套 scrollIntoView/querySelector/find text）；rule metadata 收敛到 `DocumentDiagnosticRuleRegistry`（ruleId/category/locationStrategy；severity 继续走 SeverityPolicy）。
- **六类 location 模型**：`canonical-node`（heading：stableIdentity，点击时经当前 canonical frame→live HTMLElement 重解析，禁长期持有 HTMLElement）、`source-range`（LATENT 等 source-only：startLine/startColumn，producer 起即携带 line/column/markerLevel，禁 text lookup）、`document-start`（STRICT_ZERO_H1→滚到顶部）、`document-end`（EOF 两类→GO_BOTTOM/EOF 附近）、`block-node`（figure/table/code/formula：复用 caption/block canonical identity，禁 text find-first）、`multi-target`（MULTIPLE_H1/重复标题文本：targets=[offending…]，UI 单按钮循环定位）。heading gap 定位 offending heading（H4 不是 H2）；STRICT_FIRST_H1 定位该 H1 自身。
- **Validity 与 DOM Resolution 严格分离**：
  - `validateDiagnostic()`：INVALID/CHANGED → **STALE**（提示"目标已变化，请重新检查"）；**STALE 仅限能证明 source 级变化**：原 token 删除/修改、原行删除、documentKey 切换、predicate 不再成立。
  - `resolveDiagnosticTarget()`：UNRESOLVED（DOM/语义解析失败、SOURCE_LINE_NOT_FOUND、找不到 heading/wrapper/broken-image DOM、text 不一致）**不得标 STALE**，只记录真实 resolver failure（SOURCE_LINE_NOT_FOUND 只表示该 anchor 未命中，不等于 STALE）。**消灭"DOM 解析失败 == 目标已变化"的假等价**。
  - locator 优先级：document identity → stable block identity → exact sourceRange → semantic anchor → source text+context fallback → occurrence-aware fallback（每级确定性，**禁全页无边界模糊匹配**）；revision 污染审查：outline class change/numbering decoration/scroll/selection/panel 开关等 UI mutation 不得使 source validity 变 stale。
  - **Diagnostic→Anchor→DOM→Scroll→Highlight 链路**：resolve 成功必须真实 scroll + transient highlight（`inkchapter-diagnostic-locate-highlight`，1.0–1.5s 到期移除、不写 Markdown、Edit Guard 锁定时仍允许定位，定位是 read-only navigation）；audit `[DOCUMENT-DIAGNOSTIC-LOCATE-AUDIT]` 区分 `validityDecision / resolveDecision / scrollDecision / highlightDecision / finalDecision`。
- **Resource 三层身份分离**：source token identity（判用户是否真实改 source，STALE 只依据此层）≠ resource semantic identity（归一化后"是否同一资源"）≠ DOM identity（src/data-src/href/file://，只用于 DOM resolution）。单一 canonicalizer `normalizeResourceIdentity(rawDestination, baseDocumentPath)` 覆盖 relative/absolute windows/file://、`/` `\` `./` `../`、`%20`、中文 percent-encoding；幂等测试 `normalize(normalize(x))==normalize(x)`；禁重复 decode/encode 链。duplicate occurrence 用 `{ canonicalDestination, occurrenceIndex }`（`dup.png#2` 仅 display suffix，**禁止写入 rawDestination/canonicalDestination/href/src/filesystem check**；禁 querySelector first match）。HTTP/HTTPS 与本地路径边界保留（`HTTP_LOCAL_MISSING_EXCLUSION`）。唯一正文目标定位示例：缺名复合定位见上小节；`STRICT_ZERO_H1→GO_TOP`、EOF 类→GO_BOTTOM 复用既有 Scroll Operation authority（文档级目标禁止第二套滚动实现）。
- **Locate 滚动事务（不可重入）**：单事务状态机 `IDLE→RESOLVING→SCROLLING→HIGHLIGHTING→IDLE`，全局锁在 `DocumentDiagnosticLocateController`（非单条 item 级）；busy 期间任何"定位"点击 `clickDecision=IGNORE_BUSY`、**不排队、不推进 targetIndex**（顺序：先判 busy→IGNORE；idle 才读 committed targetIndex→建事务→resolve→scroll→highlight→commit next targetIndex）。UI 进入"定位中…"disabled/aria-disabled 只是第一层，controller 逻辑锁是第二层。完成依据 = `scrollend`（支持时）或 **rAF 连续 3–4 帧 scrollTop 稳定 + 目标进入期望 viewport**（`SCROLL_SETTLED`）；**禁固定 300/500ms 解锁**（watchdog 仅异常兜底，不作正常完成判据）；目标已就位则跳过滚动立即 highlight+commit。文档切换/面板关闭/dispose → `cancel transaction`、清 highlight、release lock、**不 commit targetIndex**（identity 复验防旧 scroll completion 污染新文档）。audit `[DOCUMENT-DIAGNOSTIC-LOCATE-TRANSACTION]`（transactionId/clickDecision=ACCEPT|IGNORE_BUSY/state/completionReason/committedNextTargetIndex）。
- **Diagnostics 面板底部安全区**：`panel max-height = viewportHeight - panelTop - navigationReservedHeight - safeGap`，超出后 drawer body 内部滚动，不覆盖右下 ↑/↓，不缩窄正文（见 §2 独立 anchor 与 §5 Navigator 呈现 authority）。

## §3.1 标题编号装饰：Number + Gap 原子 reconcile（V5.14-R4）

## §5 Scroll Navigator（↑/↓）

- **单一 scroll container authority**：`resolveEditorScrollContainer()` = `#write.parentElement`（真实 `CONTENT.typ-workspace-binding`），两按钮共享；禁复制第二套 resolver。

### Navigator 呈现 authority：三态 gutter / inset / hidden（UI Phase 2-B.3 + 8B.3/8B.3.1）

- **可见性唯一 authority = 真实 scroll container 的 `maxScrollTop = max(0, scrollHeight - clientHeight)`**（epsilon=1px）；禁止用字数/标题数/DOM block 数/文档类型/固定像素判断。`navigatorExpectedVisible` 只此一处计算，NAV-PLACEMENT/BCR/audit 全部复用它，**禁止第二套 scrollability**。
- **三态 gutter/inset/hidden**：`scrollable`（maxScrollTop>epsilon）决定"要不要"，真实可见几何决定"放哪里"；**"窗口较窄"≠"隐藏"**（8B.6 宽度守卫不得强行隐藏/显示 navigator，可见性仍只随纵向 scrollability）。
  - 唯一决策纯函数 `decideNavigatorPresentation()` + 唯一 DOM writer `applyNavigatorPresentation()`；**单一 Navigator DOM 常驻单实例**，切态只改属性（class/state token），不 destroy/recreate；`gutter→inset→hidden→inset→gutter` 可逆。
  - reason 统一集：`NOT_SCROLLABLE / GUTTER_AVAILABLE / INSET_AVAILABLE / NO_SAFE_PLACEMENT / DRAWER_CONFLICT（仅真实冲突）/ EDITOR_NOT_VISIBLE`（旧误分类语义 `SHORT_DOCUMENT_NAV_HIDDEN` 只作为 8B.3 overlay audit 的 decision 名，不作为 presentation reason 分类）。
- **Safe-Rail 几何链**：`computeVisibleWriteContentRect → computeNavigatorSafeRail → computeNavigatorInsetCandidate → decide → apply → audit`。`railLeft = visibleWriteRect.right + NAV_CONTENT_SAFE_GAP`；`railRight = min(visibleEditorRect.right, scrollContainerSafeRight) - NAV_SCROLLBAR_SAFE_GAP`；`railWidth ≥ navigatorWidth + 2×NAV_RAIL_HORIZONTAL_SAFETY` 才 insetSafe；inset 不得重叠 scrollbar（scrollbar 用实测 `offsetWidth - clientWidth`，fallback 需标 `source=fallback`）；candidate 定位 `candidateRight = railRight - NAV_RAIL_INNER_GAP`。
- **三态几何知识**：`KNOWN_SAFE_GEOMETRY / KNOWN_NO_SAFE_PLACEMENT / UNKNOWN_GEOMETRY`。UNKNOWN（几何不可用/jsdom）**不得触发 NO_SAFE_PLACEMENT**（→ `GEOMETRY_UNKNOWN_FALLBACK`，非破坏性可见）；只有 KNOWN_NO_SAFE 才 hidden。
- **Position Drift 升级为 FAIL invariant `NAVIGATOR_POSITION_DRIFT`**：presentation=inset 时需 insideVisibleEditor / clearOfContent / clearOfScrollbar / fitsRail，且 `abs(actualRight - expectedRight) ≤ 1~2px`（NAV_POSITION_TOLERANCE_PX）；reason 六类：`OUTSIDE_SAFE_RAIL / TOO_CLOSE_TO_CONTENT / TOO_CLOSE_TO_SCROLLBAR / OUTSIDE_VISIBLE_EDITOR / ANCHOR_MISMATCH / WIDTH_NO_LONGER_FITS`。geometry commit 后**只读 audit**；**禁 drift→write→ResizeObserver 自修复循环**。
- **硬断言**：
  - `scrollable=true` + `SHORT_DOCUMENT_NAV_HIDDEN` = FAIL（`SCROLLABLE_DOCUMENT_MISCLASSIFIED_AS_SHORT`）；
  - `scrollable=true` + geometryKnown=false + NO_SAFE_PLACEMENT = FAIL；
  - drawer 只影响 candidate safe geometry，**不得直接写 navigator.hidden**，不恢复 `DRAWER_SUPPRESSED_NAVIGATOR_SMALL_VIEWPORT` 语义；
  - `DOCUMENT-UTILITY-NAVIGATOR-VISIBILITY-INVARIANT`：`PASS_GUTTER / PASS_INSET / PASS_HIDDEN_NOT_SCROLLABLE / FAIL_*`；
  - navigator 隐藏时必须 `display:none`（不可点击/聚焦/键盘可达）。
- 8B.3.1 audit closure 语义：`navigatorExpectedVisible=false` → `NAV_PLACEMENT=NOT_EVALUATED / NAVIGATOR_EXPECTED_HIDDEN`、BCR `navigatorState=EXPECTED_HIDDEN`（区别于 `GEOMETRY_PENDING`），`HIDDEN_NAV_FALSE_POSITION_DRIFT_COUNT=0`；Drawer rerender audit 只读（`geometryWriteDelta=0`）；Resize `feedbackLoopConfirmed` 需同一 causal token 闭环证明，echo/suspect 不得升级（该 Hard Gate 在后续 UI 阶段仍须保持 `feedbackLoopConfirmedCount=0`）。
- **EMPTY / 无活动文档 → navigator 一律 hidden（Navigator Empty-Workspace Ghost Control V1）**：资格判定最高优先门是 `NO_ACTIVE_DOCUMENT`（EMPTY leaf / 无 documentKey / surface 未连接 / empty untitled）；此时 navigator 必须 `hidden`，**禁止**退化为左下角 / 底部 fallback 位置。DOM 默认挂载即 hidden，只有"真实 scrollability + 真实放置几何"齐备才切 gutter / inset。测试 `document-utility-navigator-empty-workspace-ghost-v1-7r3-11-8b81.test.ts`。

### Scroll Operation settle authority（7R.3.11.8/8B）

- **删除固定 250ms 业务 authority**；固定 deadline 只能作安全退出（2000ms），不能作成功判据；"把 250ms 改大"是假修复。
- 每次按钮点击一个 **有限 `ScrollOperation`**：operationId/documentKey/action/source/container/`targetAtStart`/`maxScrollTopAtStart`/scrollEventCount/state。
- target 在 execution 时读取；**settle 时重读 live target**（targetDelta）；subpixel epsilon = 1px（324.8/325）。

- **`SETTLED_BEFORE_TARGET` 最多一次 corrective**（`behavior:'auto'` 直接定位）→ `PASS_RECOVERED`；仍失败 → `FAIL_SETTLED_BEFORE_TARGET`；禁 while/递归 setTimeout/interval/无限重试。
- 生命周期安全：document switch（`CANCELLED_DOCUMENT_SWITCH`）、container disconnected（`FAIL_CONTAINER_DISCONNECTED`）、dispose、新操作 supersede 全部解绑；结束资源清零（activeScrollOperationCount=0 等）。
