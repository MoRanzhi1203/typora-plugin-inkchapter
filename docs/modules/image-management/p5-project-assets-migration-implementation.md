## 2. 扫描（只读）

`scanProjectImages({ projectRoot, assetRoot })`：

- 项目根与资源根由调用方显式给出，不推断 sibling Markdown 是否属于同一项目。
- 扫描项目内 `.md`，排除 `.git`、`node_modules`、`.inkchapter`、`dist`、`.typora`。
- 不跟随符号链接，避免越界。
- 复用统一引用扫描：行内、参考式、HTML；代码块/行内代码中的示例不算引用。
- 报告：
  - 被引用资源及其引用文档、引用 ID、原始目标；
  - 未被引用图片；
  - 资源根中的非图片文件；
  - 缺失本地引用；
  - 位于资源根之外的本地引用（只报告，不迁移）；
  - 扫描截断标记与读取失败项。

## 3. 迁移计划（只读）

`planProjectImageMigration({ projectRoot, assetRoot, targetDirectory })`：

| 规则 | 行为 |
|---|---|
| 目标目录 | 必须是项目内相对路径，拒绝绝对路径、`..`、磁盘根 |
| 重复层级 | 拒绝 `assets/assets`、`images/images`、`Project/Project/assets` |
| 目标等于资源根 / 包含资源根 | 直接判定问题，不生成计划 |
| 已被移动的资源 | 位于目标目录内的资源不再重复迁移 |
| 未引用图片 | 默认不迁移，只在报告中列出；可显式包含 |
| 同名同内容 | 复用已有目标，不复制、不覆盖 |
| 同名异内容 | 用 `<原名>-<sha8>.<ext>` 消歧，绝不覆盖 |
| 跨盘引用 | 记为 `CROSS_DRIVE_REFERENCE`，不生成相对路径 |
| 长路径 | 目标绝对路径超过 240 字符时给出警告 |
| 引用改写 | 仅改写真实图片目标偏移，保留代码块内容 |

计划会记录每篇文档的 SHA-256 与每处引用的原始偏移，供执行阶段复核。

## 4. 执行与回滚

`executeProjectImageMigration(plan, { backupDir, isDocumentOpen? })`：

1. 拒绝仍在编辑器打开的文档（若运行时提供检测回调）。
2. 重新计算每篇文档哈希；与计划不一致则 `DOCUMENT_CHANGED`，不写任何文件。
3. 备份所有将被改写的文档到迁移日志目录。
4. 复制图片到目标：临时文件 → SHA-256 校验 → rename；目标已有不同内容则拒绝。
5. 按引用偏移倒序改写文档，临时文件 + rename 原子替换。
6. 逐条解析新引用，确认真实文件存在；任一失败自动恢复文档并删除本次新建副本。
7. 默认保留旧图片；迁移成功后写 `applied` 日志。

`rollbackProjectImageMigration(journalPath)`：

- 恢复文档备份、删除本次复制的目标；
- 若迁移后文档又被编辑（当前哈希 ≠ 写入时哈希），**拒绝回滚**，避免覆盖用户新内容；
- 旧图片默认未被删除，回滚后文档重新指向旧路径。

`cleanupProjectImageSources(journalPath)`：

- 只在 `status = applied` 后可用；
- 逐文件确认目标存在且 SHA-256 一致后才删除旧文件；
- 必须由用户显式确认后调用，不是自动清理。

## 5. Typora 原生语义

- 迁移只改变「已有图片放在哪、文档怎么写」，不会修改 Typora 的“复制图片到 ./assets”原生目标。
- 若用户希望以后插入的图片直接进入新目录，需要使用 Typora 原生“复制到指定路径”，或由用户自行调整 Typora 设置。
- 当前 `test/vault/assets` 的扁平结构保持不变；本阶段没有对测试 vault 执行任何迁移。

重点用例：
