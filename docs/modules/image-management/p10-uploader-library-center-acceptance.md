## 3. P10-B 上传器

### 3.1 设计约束

1. 走 PicGo 编程 API（`new PicGo(configPath)` + `upload([file])`），不启动未隔离的 CLI 进程。
2. 配置固定为插件私有路径 `<插件数据目录>/picgo/config.json`；不读取、不复制用户全局 `~/.picgo/config.json`。文件缺失时直接失败，不静默回退到全局配置。
3. 上传前把源文件复制到暂存目录并重命名为安全名；源文件与原始文件名保持不变。
4. 只采信 PicGo 返回的真实 URL；空数组、空 URL、私网/本地地址一律判失败。
5. 失败分类为稳定错误码，日志不包含响应正文、路径或凭据。

### 3.2 安全命名

| 策略 | 结果 | 说明 |
|---|---|---|
| `timestamp-hash`（默认） | `YYYYMMDD-HHmmss-<sha10>.<ext>` | 不含 `#`、`%`、空格、反斜杠；同内容不会二次上传冲突 |
| `original-name` / `custom` | `<清洗后原名>-<sha8>.<ext>` | 保留可读性，仍带短哈希保证唯一 |

扩展名只接受 `[a-z0-9]{1,8}`；缺失或非法时回退为 `.img`。

### 3.3 错误码

`UPLOAD_SERVICE_NONE`、`REMOTE_PROFILE_MISSING`、`REMOTE_PATH_INVALID`、`FILE_NOT_FOUND`、`FILE_NOT_READABLE`、`STAGING_FAILED`、`PICGO_UNAVAILABLE`、`PICGO_CONFIG_MISSING`、`PICGO_EMPTY_RESULT`、`PICGO_INVALID_URL`、`INDEX_WRITE_FAILED`。

### 3.4 未完成

- 插件私有 PicGo 配置的创建与系统凭据读取尚未产品化；当前要求由用户/运维在插件数据目录放置 PicGo 配置。
- PicGo 模块需在运行时可见（全局安装或 `INKCHAPTER_PICGO_MODULE` 指定路径），未加入仓库依赖。
- 未做真实网络故障注入（断网、限速、写入中断）。

### 3.5 上传入口（P10 追加）

- 命令面板：「墨章：上传本地图片…」（`inkchapter.image.upload-local`）。
- 设置页「图库中心」区域：「上传本地图片…」按钮。
- 行为：原生文件选择 → 墨章上传器 → 显示真实 URL 并尝试复制到剪贴板；**不修改当前 Markdown、不删除源文件**。
- 上传服务为 `none` 时直接提示并打开设置指引，不弹出文件选择。
- 真实上传仍依赖插件私有 PicGo 配置；缺失时返回 `PICGO_CONFIG_MISSING`。
- 运行时已验证：命令出现在命令面板，远程图床显示「已配置」且上传服务为「GitHub」。

## 4. 插入方式冲突提示

- 读取 Typora `profile.data`（十六进制编码 JSON，兼容直接 JSON），仅解析 `image_save_location` 与 `image_uploader`。
- `image_save_location = ipic` 判定为「上传图片」；其余为本地复制；缺失/损坏为未知。
- 当且仅当「上传图片」+ 墨章上传服务为 `none` 时提示；不修改 Typora 首选项、不删除图片、不写入远程链接。
- 运行时验证：命令「墨章：图片图库中心」的提示框包含完整冲突文案。

## 5. P10-C 四视图图库中心与任务队列

### 5.1 视图

| 视图 | 数据来源 | 行为 |
|---|---|---|
| 当前文档 | 当前 Markdown 引用 | 未索引引用只显示「未索引」，不谎称可用或缺失 |
| 本地图库 | 资产的项目/图库/离线位置 | 按 availability 显示可用/缺失/未知 |
| 云端图库 | 资产的 GitHub 位置 | 只展示历史记录，不联网探测 |
| 任务与诊断 | 传输任务 + 配置 | 上传服务、Typora 插入方式、冲突提示、目录与缓存占用 |

- 视图模型为纯函数，不操作 DOM、不新增 MutationObserver、不改变图号/题注样式。
- 设置页「图库中心」区域只读渲染，提供「刷新」按钮；命令面板提供同名入口。
- 任务持久化位于 `<插件数据目录>/transfer-tasks.json`，使用临时文件 + rename；文件损坏时只报错、不覆盖。

### 5.2 状态分离

上传任务失败只更新任务状态与错误码，不改变资产 `availability`；资产可用性仍由真实位置决定。
