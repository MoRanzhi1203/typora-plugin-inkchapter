## 2. 引用状态

| 状态 | 判定 |
|---|---|
| `LOCAL_ONLY` | 项目 / 图库 / 离线固定中至少一个真实可用，无已验证远端 |
| `REMOTE_ONLY` | 有已验证 GitHub 位置，无永久本地副本 |
| `DUAL_AVAILABLE` | 永久本地副本与远端同时可用 |
| `cache-only`（展示态） | 只有普通缓存；存储状态仍为 `REMOTE_ONLY` / `LOCAL_ONLY`，不冒充双存储 |
| `unavailable` | 没有任何可用落点 |

上传待办、失败、远端失效仍使用 `availability` 与任务记录表达，不并入本枚举。

## 3. 缓存策略

| 模式 | 行为 |
|---|---|
| `off` | 不写任何缓存，不承诺离线显示 |
| `smart` | 远端图片、无永久本地副本、尚未缓存时按需缓存 |
| `manual` | 只有用户显式指定才缓存 |

安全与去重：

- 只允许 `http/https`，拒绝 URL 内嵌凭据、回环、私网、链路本地与 `.local` 主机；重定向后的最终地址再次校验。
- 内容类型必须是 `image/*` 或 `application/octet-stream`；超过下载上限直接拒绝。
- 对象按 SHA-256 命名，同一内容只存一份；不同 URL 引用同一内容不会重复占空间。
- 缓存索引损坏只影响缓存，不阻断插件；用户图库、项目文件、固定离线不在缓存范围内。
- LRU 清理按「内容对象」计算；只要有一个受保护 URL 引用该对象，就整体保留。

## 4. 固定离线资源

`prepareDocumentOffline`：

- 本地已有图片：直接核验可用，不复制、不下载。
- 远端图片：优先复用缓存对象并复制为受保护离线对象；否则下载到 `OfflineAssets/objects/`。
- 写入本地清单 `<offlineManifestsDir>/<documentKey>.json`，只记录文档名、来源（远程 URL 或本地文件名）、相对对象路径、SHA-256、大小与状态。
- `verifyDocumentOffline` 重新检查对象存在性与哈希，如实报告缺失；本地项目文件不计入对象核验。

清单不包含用户绝对路径，也不包含凭据。

## 5. 离线工作副本（保底路径）

`createOfflineWorkingCopy`：

1. 复制已有本地图片、下载缺失远端图片到副本 `assets/`；
2. 资源名使用短哈希 + 序号，避免空格、`#`、`%` 与重名；
3. 只替换副本中的图片目标范围，代码块内引用保持不变；
4. 输出 `<name>.offline.md`，原 Markdown 完全不变。

## 6. Typora 透明离线回退门槛

本阶段**不宣称**支持「保持原远程 URL 且断网可用」：

- 未找到经过运行时验证的安全渲染接入点；
- 不使用高频 MutationObserver、协议劫持或覆盖渲染节点；
- 不修改原 Markdown。

因此采用第 5 节的离线工作副本作为受支持保底方案。若后续验证出稳定、事件化的渲染钩子，再单独评估。

重点用例：

- `smart` 首次缓存、二次复用；`manual` 必须显式；`off` 不写盘。
- 同一内容两个 URL 只存一个对象。
- 超出配额按 LRU 清理；受保护 URL 不被清理。
- 私网 / 回环 / 非图片 / 超限下载被拒绝。
- 本地文件不重复下载；缓存对象可复用为离线资源。
- 删除离线对象后核验如实报告缺失。
- 离线工作副本只改写副本，代码块引用保持不变。

## 8. 未完成与风险

1. 缓存与离线服务尚未接入设置页/命令（P7）。
2. 断网、上传中断、远端 404/410、超大图与并发下载尚未做真实 Typora 运行时验收。

4. 离线清单不记录原始本地绝对路径，因此无法自动核验本地项目文件是否仍存在；该核验留在引用扫描层。
