## 1. 它是什么

墨章 InkChapter 是一个 **Typora 社区插件**，目标是让 Markdown 文档在**结构、编号、题注、排版、检测、图片工作流**上更接近正式论文/报告的写作体验，同时不改变 Typora 的编辑习惯。

它解决的核心问题：

| 问题 | 墨章的解法 |
|---|---|
| 手动维护标题编号（1、1.1、1.1.1…）极易错位 | 自动编号 + 多级格式 + 文档级覆盖 |
| 图表/代码块没有编号与题注 | 图表题注系统（图/表/代码 + 语义编号） |
| 空行、标题层级、图片语法等问题肉眼难查 | 文档检测（诊断列表 + 定位 + 安全修复） |
| 图片散落本地/远程，上传下载靠手工 | 图片管理中心（策略、批量上传/下载、双链） |
| 大纲、正文、题注编号不一致 | 单一编号权威 + 大纲同步 |

## 2. 安装、启动与加载

### 2.1 安装位置

| 场景 | 插件位置 |
|---|---|
| 仅在某个 vault 内使用 | `<vault>/.typora/plugins/dist/` |
| 任意 Markdown 文件使用（用户级） | `%APPDATA%\Typora\plugins\plugins\<插件 id>` |

社区框架会按「打开的是文件夹（vault）」或「单独文件」选择加载来源。插件每次启动会写一份加载回执 `<vault>/.typora/inkchapter-runtime-load.json`，可用于确认**到底是哪一份构建在运行**。

### 2.2 验证是否加载成功

1. 用 Typora「打开文件夹」打开你的 vault（而不是只打开一个 `.md`）。
2. 打开任意 Markdown 文档。
3. 编辑器**右上角**出现一个 12px 三色小方块 → 插件已加载。
4. 排障：查看 `<vault>/.typora/inkchapter-runtime-load.json` 中的 `loadSource`（`vault` / `global`）与 `mainJsSha256`。

> 提示：如果换了新构建但界面没变化，通常是因为 Typora 仍在使用旧进程。彻底退出 Typora 再打开即可。

## 3. 界面地图：先认这 7 个入口

| # | 入口 | 位置 | 打开方式 | 主要用途 |
|---|---|---|---|---|
| 1 | 文档状态方块 | 编辑器右上角 | 单击展开 / 双击锁定切换 | 检测、图片、锁定三合一 |
| 2 | 内容块工具栏 | 代码块 / 表格 / 图片/公式块悬浮 | 鼠标悬停 | 复制源码、复制图片、图名、下载 |
| 3 | 滚动导航器 | 右下角（竖向按钮） | 点击 ▲▼ | 长文档快速滚动 |
| 4 | 侧栏大纲编号 | Typora 原生侧栏「大纲」 | 自动同步 | 编号与正文一致 |
| 5 | 文档标签右键菜单 | 标签页标题 | 右键 | 关闭全部 / 复制路径 / 资源管理器 |
| 6 | 设置工作台 | Typora 设置 → 墨章 | 打开设置页 | 编号方案 / 标题格式 / 文档规则 / 图表对象 |
| 7 | 命令面板 / 快捷键 | Typora 菜单 | `墨章：…` 开头的命令 | 编号切换、诊断、批量操作 |

### 3.1 文档状态方块（最常用）

- **形状与颜色**：12px 纯色方块。绿色＝无问题，黄色＝有警告，红色＝有错误，灰色＝未知/未检查。
- **单击**：向左展开三标签面板。
  - **检测**：直接显示真实诊断列表（不是摘要页）。
  - **图片**：当前文档图片策略与一键操作。
  - **锁定**：锁定/解锁当前文档。
- **双击**：只切换真实锁定状态（不会打开面板）。
- **锁定后**：方块外围出现 1.5px 中性细框，同时阻止正文写入（修复按钮会提示先解锁）。

### 3.2 内容块工具栏

鼠标悬停在代码块、表格、图片、公式块上时出现：

- 代码块：复制源码、展开/折叠预览（默认预览 5 或 10 行，可在设置中切换；编辑时自动展开）。
- 图片：复制图片、下载远程图片、为图片命名（接入题注/编号服务）。
- 表格：与题注/编号联动。

> 这是**悬浮工具条**，不会改写正文；所有写操作都走 Typora 的编辑事务。

## 4. 十分钟上手

按顺序做完这 5 步，就能覆盖 80% 的日常使用：

1. **打开 vault**：Typora → 打开文件夹 → 选择你的文档目录。
2. **打开一篇文档**：右上角出现三色方块。
3. **打开设置工作台**：Typora 设置 → 墨章 → 选择「编号方案」预设（如「中文章节」）→ 保存。
4. **写三个标题**：`#`、`##`、`###`，观察编号自动出现，并且左侧大纲同步。
5. **点开右上角方块 → 检测**：查看列表 → 点一条诊断 → 使用「定位」或「修复」。

## 5. 功能详解

## 5.1 标题自动编号

**是什么**：为 H1–H6 自动生成编号（`1.`、`1.1`、`第一章`、`一、`…），并保证重排、插入、删除后自动重算。

**怎么做**

1. 打开设置 → 墨章 →「编号方案」。
2. 选择预设（5 种）：
   - `十进制层级`（1 / 1.1 / 1.1.1）
   - `中文章节`（第一章 / 1.1）
   - `中文大纲`（一、/（一）/ 1.）
   - `罗马数字`
   - `空白`（不编号，仅保留排版）
3. 需要更细致时进入「标题格式」页：为每个级别单独设定
   - 是否启用、数字样式（阿拉伯/全角/中文/大写中文/带圈/大小写字母/希腊字母/天干/地支/罗马）、
   - 分隔符、前后缀、起始值、重新开始规则、
   - 组合格式（含/不含一级标题、上下文格式）。
4. 文档级覆盖：同一篇文档可以有自己的编号设置；命令「取消/启用当前标题编号」「恢复继承」可对**当前标题**或**当前标题及下级**生效。

**注意**

- 编号是**装饰投影**，不会写进 Markdown 源文本；导出/复制源码时不会带编号。
- 手动输入「1.1」这类编号会触发诊断 `HEADING_MANUAL_NUMBER_PREFIX` / `HEADING_AUTO_NUMBER_CONFLICT`。

详见 [heading-numbering.md](modules/heading-numbering.md)、[numbering-presets.md](modules/numbering-presets.md)、[custom-multilevel-format.md](modules/custom-multilevel-format.md)、[document-scoped-settings.md](modules/document-scoped-settings.md)。

## 5.2 标题格式与排版

**是什么**：每个标题级别的对齐方式、首行缩进、编号与标题之间的间距。

**怎么做**

1. 设置 → 墨章 →「标题格式」→ 级别表（H1–H6）。
2. 逐级设置：对齐方式、首行缩进（仅居左有效）、标题间距。
3. 批量操作：`全部左对齐 / 全部居中 / 全部右对齐 / 全部无缩进 / 全部缩进2字符 / 全部无间距 / 全部一个空格 / 全部恢复默认`。
4. 段落首行缩进快捷方式：在段落开头输入 `..` 或 `。。` 再按 `Enter`，该段落强制首行缩进；命令「强制顶格当前段落」「恢复当前段落自动缩进」可逐段调整。

详见 [heading-layout.md](modules/heading-layout.md)。

## 5.3 标题结构模式：Strict / Loose

**是什么**：两套标题层级校验与排版规则。

- **Loose（默认）**：按层递减即可，不强制「首块必须是 H1」，也不强制唯一 H1。
- **Strict**：适用于论文/报告，额外要求
  - 首个内容块必须是 H1；
  - 只允许一个 H1；
  - 层级不能跳级。

**怎么做**

1. 设置 → 墨章 →「文档规则」→ 选择标题结构模式（全局默认）。
2. 需要时在文档级覆盖（同一文档单独设置）。
3. 状态与违规会出现在检测列表（`STRICT_FIRST_H1`、`STRICT_SINGLE_H1_NO_H1`、`STRICT_SINGLE_H1_MULTIPLE_H1`、`HEADING_LEVEL_GAP`）。
4. 命令「墨章：切换标题结构模式」可快速切换。

详见 [strict-loose-heading-structure.md](modules/strict-loose-heading-structure.md)、[heading-range-control.md](modules/heading-range-control.md)、[special-heading-rules.md](modules/special-heading-rules.md)。

## 5.4 大纲编号同步

**是什么**：把正文标题编号同步到 Typora 左侧「大纲」面板。

**怎么做**

1. 保持默认开启（无需额外设置）。
2. 若发现大纲未刷新：命令「墨章：立即同步大纲编号」。
3. 排障：命令「墨章：诊断大纲编号」「墨章：导出大纲DOM诊断」。

**行为约定**：大纲的编号前缀是**独立的投影**，不改大纲文本内容、不影响点击跳转。

## 5.5 公式编号

**是什么**：为块级公式（`$$…$$`）分配编号，并支持「节内编号」（如 `1.1-1`）或全局编号。

**怎么做**

1. 设置 → 墨章 →「图表对象」→ 公式编号：开启、选择作用域（全局 / 节内）、编号模板。
2. 在正文插入块级公式；编号按当前生效规则显示。
3. 空公式块也会占用编号（不会出现编号空洞）。

**注意**：公式是 Typora 的渲染块，插件不会改写公式源码；编号只做显示投影。

**写入源码（R10）**：在设置 →「文档规则」→「图表代码公式编号」中把存储模式切换为「源码持久化」后，公式编号会写成独立的 `（1-1）` 段落（已有 `\tag{…}` 则只更新标签内容），不会把普通文本拼进 LaTeX。关闭墨章后，`（1-1）` 仍是普通 Markdown 文本，可被任何编辑器阅读。多行公式、`aligned`、`cases`、`matrix`、空公式块与已有 `\tag` / `label` 都不会被破坏。

详见 [formula-numbering.md](modules/formula-numbering.md)。

## 5.6 图表题注（图片 / 表格 / 代码）

**是什么**：为图片、表格、代码块添加统一编号与题注，并支持独立计数。

**怎么做（三种入口）**

1. **内容块工具栏**：鼠标悬停图片 →「命名」→ 输入名称 → 确认。
2. **检测面板修复**：若出现「图片缺少题注」类诊断，点击「修复」→ 输入名称 → 预览 → 确认。
3. **设置页默认值**：设置 → 墨章 →「图表对象」→ 分别配置图/表/代码的
   - 是否启用、前缀（图/表/代码）、位置（上方/下方）、
   - 编号方式（连续 / 按 H1 / 按 H2 / 按 H3 重置 / 章节联动 / 自定义）、
   - 数字样式（阿拉伯、补零、中文、大写中文、罗马、字母）、起始值、最小位数、模板。

**注意**

- 名称保存在墨章的题注服务中，重复命名不会重复编号。
- 图片必须**独占一个块**（1 个对象 = 1 个独立块 = 1 个编号目标）；标题内、列表内、引用内、表格内的图片会被诊断并提示结构调整。

详见 [caption-system.md](modules/caption-system.md)。

### 5.6.1 图表代码公式编号写入源码（R10）

**是什么**：把图片 / 表格 / 代码块 / 公式的编号与题注真正写入 Markdown，而不是只靠插件显示。

**怎么做**

1. 设置 →「文档规则」→「图表代码公式编号」→ 选择「源码持久化」。
2. 选择已有题注处理策略：接管并同步 / 移除并重新生成 / 保留且不叠加 / 只检测。
3. 点击「将编号写入源码」或「接管已有题注」；也可执行命令面板中的同名命令。
4. 之后插入、删除或移动章节，再点「重新同步编号」即可更新章节前缀。

**写入后的样子**

```markdown
![示例图片](assets/example.png)

图 1-1 示例图片
```

```markdown
表 1-1 实验结果

| 方法 | 准确率 |
|---|---|
| A | 95% |
```

````markdown
代码 1-1 数据读取程序

```python
import pandas as pd
```
````

```markdown
$$
E=mc^2
$$

（1-1）
```

**保证**

- 只改题注行或 `\tag{…}`，不改图片路径、表格结构、代码围栏内容与 LaTeX 正文。
- 同一题注只会绑定一个对象；图片下方、表格上方的相邻题注不会同时归属两个对象。
- 重复执行同步零补丁；第二次不会追加第二套题注。
- 源码持久化模式下题注服务不再投影第二套题注，正文/导出/源码只显示一套。
- 已有 `图 1-1`、`图1-1`、`图 2.3`、`表 1-1`、`代码 1-1`、`（1-1）` 与 `\tag{}` 都能识别；普通正文里以「图 1-1」开头且以句号结尾的句子不会被误认为题注。
- 关闭墨章后，源码中的编号与题注仍然可读。

**导出**：「导出带编号副本」会同时固化标题编号与图/表/代码/公式题注，生成 `*.numbered.md`，不修改正在编辑的文档。HTML/PDF/Word 的最终排版由 Typora 宿主导出完成；编号已是源码文本，不依赖插件运行时 CSS。

详见 [caption-system.md](modules/caption-system.md) 与 [formula-numbering.md](modules/formula-numbering.md)。

## 5.7 文档检测（诊断）

**是什么**：实时扫描当前文档，把结构问题列成可定位、可修复的清单。

**怎么做**

1. 查看右上角方块颜色 → 单击 →「检测」标签。
2. 顶部是**真实计数概要**（错误/警告/提示），下面是按文档位置排序的诊断列表。
3. 每条诊断显示：严重级别、`Lxx` 行号、规则文案。
4. 点击一条 → 执行真实定位（滚动 + 高亮 + 行内提示），不改变正文。
5. 可修复项：
   - **修复**：只修当前这一条；
   - **同类修复**：修同一规则的所有实例（存在多项时出现）；
   - **一键修复可处理项**：一次处理当前快照中所有安全项。
6. 顶部图标可「重新检测」。

**诊断覆盖范围**（按域分组）

| 域 | 示例规则 |
|---|---|
| 标题结构 | 层级跳跃、空标题、严格模式首块/单 H1、标题仅文本 |
| 文档结构 | 空文档、仅标题、章节无正文、仅子标题 |
| 空行与换行 | 内部多余空行、文末空行过多、文末缺换行、文首空行 |
| 编号一致性 | 手动编号前缀、自动编号冲突、图表编号重复/乱序、公式节号不匹配 |
| 图片 | 路径为空、语法未闭合、位于标题/列表/引用/表格、多图同段、独立块结构异常 |
| 表格 | 表头为空/重复、列数不一致 |
| 代码 | 代码围栏未闭合、缺少语言 |
| 公式 | 单行块公式、公式块未闭合 |
| 链接/脚注 | 引用链接缺失/重复、脚注未定义/未使用/重复、Front Matter 未闭合 |

> 库存文档记录当前已实现 87 条规则，完整代码与条件见 [DOCUMENT_DIAGNOSTICS_FULL_INVENTORY.md](diagnostics/DOCUMENT_DIAGNOSTICS_FULL_INVENTORY.md)。

**安全约定**

- 面板不会隐藏真实问题；「修复成功」必须由**修复后的重新检测**证明。
- 修复写入使用 Typora 自身的编辑事务，可用一次 `Ctrl+Z` 撤销。

详见 [document-diagnostics.md](modules/document-diagnostics.md)、[document-utilities.md](modules/document-utilities.md)。

## 5.8 空行规范与空行修复（重点）

**是什么**：一套统一的空行规则 + 可安全执行的自动修复。

**空行矩阵（渲染层额外空行目标）**

| 相邻结构 | 额外渲染空行 |
|---|---:|
| 正文 → 正文 | 最多 1 |
| 正文 → 标题 / 标题 → 正文 / 标题 → 标题 | 0 |
| 正文 ↔ 代码块 / 公式块 / 图片 / 表格 | 0 |
| 特殊块 ↔ 特殊块 | 0 |
| 文首 | 0 |
| 文末 | 恰好 1 个换行 |

> 关键约定：**Markdown 源码中 1 个结构分隔空行不算「多余空行」**。正常排版不会被误报。

**怎么做**

1. 打开「检测」→ 找到 `连续空行过多` / `文档末尾空行过多` / `文档开头空行过多`。
2. 点击「修复」：只删除**目标区间**的多余空行，保留 1 个结构分隔空行。
3. 若同时存在多处：点「一键修复可处理项」。
4. 改错了：`Ctrl+Z` 一次撤销；`Ctrl+Y` 重做。

**过期诊断（你在检测后又编辑了文档）**

- 点击修复时，插件会**读取当前文档重新检测**，并按稳定块身份找到原目标继续修复；
- 若目标已被删除或出现多个同类候选，则**不写入**，只刷新检测列表并提示，绝不按旧行号误删。

**已由运行时验收证明的行为**

- 单项修复的缓冲区结果与「只应用该条补丁」的纯计划结果**逐字节一致**；
- 修复后文末换行、非目标空行区间保持不变；
- 撤销后文档与修复前逐字节一致，重做恢复修复结果；
- 一键修复后空行诊断归零、列表/计数/行号/可修复数量同步刷新。

验收脚本与证据见 [BLANK_LINE_R06_RUNTIME_ACCEPTANCE.md](diagnostics/BLANK_LINE_R06_RUNTIME_ACCEPTANCE.md)。

## 5.9 文档锁定

**是什么**：临时禁止对当前文档正文的写入（只读保护）。

**怎么做**

1. 右上角方块 → 双击，或「锁定」标签 → 点击。
2. 锁定后：方块出现外框、编辑与修复被阻止。
3. 再次双击解锁。

**注意**：锁定是插件级保护，不是 Typora 的只读模式；它保证「检测修复」等自动写入不会在你审阅时改动正文。

## 5.10 滚动导航器

**是什么**：右下角的 ▲▼ 浮动导航，用于长文档快速滚动。

**怎么做**

1. 点击 ▲ / ▼ 滚动一屏。
2. 打开 Typora 原生字数统计面板时，导航器会自动避让（左移 / 上移 / 隐藏）。

**行为约定**：一次手势只执行一次滚动意图；不改变选区与光标。

## 5.11 图片管理

**是什么**：统一的图片策略与上传/下载能力。

**怎么做**

1. 设置 → 墨章 →「图片管理」。
2. 关键设置：
   - **存储与引用**：文档资源目录、存储模式、引用模式；
   - **上传服务**：GitHub / PicGo 等远程方案，支持多 profile；
   - **自动化**：插入时自动本地化、自动上传；
   - **命名与压缩**：命名策略、压缩模式、转换为 WebP；
   - **缓存与离线**：缓存目录/上限、离线策略；
   - **并发与重试**：上传/下载并发、重试次数、单文件大小上限。
3. 凭据只保存在本地凭据引用中，不会明文写进文档或提交到仓库。

## 5.12 文档管理中心（图片页）

**怎么做**

1. 右上角方块 →「图片」。
2. 顶部显示当前文档图片策略与统计（可上传 / 可下载 / 缺失 / 可复用）。
3. 操作：
   - **上传全部**：把本地图片按当前策略上传（复用已有远程内容，不重复上传）；
   - **下载全部**：把远程图片下载到本地目录；
   - **检查并补齐双链**：检查本地/远程双链，缺失时补齐；
   - **图片设置**：跳到图片设置页。

**安全约定**：批量操作先**预检 → 确认 → 执行**；默认不改写 Markdown，不创建未授权目录。

详见 [document-hub-and-image-batch.md](modules/document-hub-and-image-batch.md)。

## 6. 典型工作流（分步剧本）

## 剧本 A：写一篇带自动编号的论文

1. 打开 vault 与文档。
2. 设置 → 墨章 →「编号方案」→ 选「中文章节」。
3. 「文档规则」→ 标题结构模式选 **Strict**（论文推荐）。
4. 写 `# 第一章标题`、`## 小节`、`### 子节`，编号自动出现，左侧大纲同步。
5. 右上角方块 →「检测」：修复严格模式下的首块 / 单 H1 提示。
6. 需要局部例外时：右键当前标题 →「从此标题开始停止编号」。

## 剧本 B：给图片、表格、代码加题注

1. 设置 →「图表对象」：图（下方，前缀「图」）、表（上方，前缀「表」）、代码（上方，前缀「代码」）。
2. 插入一张独占一段的图片。
3. 悬停图片 → 工具栏「命名」→ 输入名称。
4. 检测面板确认「图片缺少题注」消失；编号按章节/连续规则显示。

## 剧本 C：清理文档里的多余空行

1. 检测 → 找到「连续空行过多」等条目。
2. 「一键修复可处理项」。
3. 检查：块之间只剩 1 个结构分隔空行，文末恰好 1 个换行。
4. 不满意：`Ctrl+Z` 撤销；`Ctrl+Y` 重做。

## 剧本 D：图片统一本地化 + 上传

1. 设置 →「图片管理」：目标目录 `assets`，开启「插入时自动本地化」。
2. 粘贴远程图片 → 自动下载到本地。
3. 方块 →「图片」→「上传全部」→ 预检 → 确认。
4. 若需要双链：点「检查并补齐双链」。

## 剧本 E：审阅时禁止改动

1. 双击右上角方块 → 锁定。
2. 审阅结束再次双击解锁。

## 9. 常见问题与已知限制

### 9.1 常见问题

| 现象 | 处理 |
|---|---|
| 右上角没有三色方块 | 确认打开的是**文件夹**（vault）；查看 `inkchapter-runtime-load.json`；彻底退出 Typora 重开 |
| 编号没更新 | 命令「重新编号标题」；或检查文档级覆盖是否把编号关掉了 |
| 大纲编号与正文不一致 | 命令「立即同步大纲编号」；仍有问题导出大纲诊断 |
| 修复按钮点不动 | 文档被锁定 → 解锁；或该规则不支持自动修复（用「定位」查看原因） |
| 修复后仍有该诊断 | 说明这次修改没有真正解决问题；面板不会假装「修复成功」 |
| 空行修复提示「无法唯一定位」 | 检测后文档改动太大、出现多个同类候选；插件已刷新列表，请按最新结果再操作 |
| 图片批量操作不可用 | 当前文档无图片 / 图片管理未启用 / 有未保存状态 |

### 9.2 已知限制（如实记录）

1. **真实鼠标点击检测面板**未做自动化验收：Typora 1.6.7 不暴露 UI Automation 树，CDP 无页面目标，系统前台焦点易被抢占。代码级与 Runtime 业务入口验收已完成，但"鼠标点击"链路仍以人工验证为准。
2. **像素级视觉门禁**（`PIXEL_GATE`）仍为人工目检。
3. 空行装饰标记在部分文档/缩放下不绘制（`blankMarkerCount=0`），此时标记断言只能证明"不残留"。
4. `Ctrl+Z / Ctrl+Y` 通过 Typora 自身命令栈验证；物理按键在焦点被抢时无法稳定自动化。
5. 大文档（数千行）实时检测仍在持续优化，极端情况下可能有输入延迟。
